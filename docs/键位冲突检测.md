# 键位冲突检测

jcode 运行在终端里，终端运行在操作系统里。两层都可能在按键到达 jcode 之前就占用它（例如 Ghostty 把 `Ctrl+Tab` 绑定到"下一个标签页"，或 macOS 把 `Cmd+Space` 绑定到 Spotlight）。发生这种情况时，jcode 的某个键位会静默地什么都不做，而且原因不明显。

该功能发现机器上存在的键位绑定，与 jcode 自己配置的绑定比较，并警告重叠。

## 能检测到什么、不能检测到什么

**可以检测（配置声明的拦截）：**

- **macOS 系统快捷键**，从 `com.apple.symbolichotkeys` 读取（Spotlight、Mission Control、截图、输入源切换等）。只考虑*已启用*的快捷键。
- **终端模拟器绑定。** 目前是 Ghostty，通过 `ghostty +list-keybinds`，它报告*生效的*绑定集（内置默认与用户配置合并）。这也能捕获重写，例如 Ghostty 将 `Alt+Left`/`Alt+Right` 映射到单词导航转义序列。

**不能检测：**

- 临时重映射器（Karabiner-Elements、BetterTouchTool）、窗口管理器或未存储在我们要读的文件中的全局启动器热键。
- Ghostty 以外的终端（目前）。添加一个是一个自包含的适配器（见下文"添加终端适配器"）。

这是启动时拍摄的快照，不是实时钩子，因此在 jcode 运行期间做出的更改要等到快照刷新后才能看到。

## 如何呈现

- **`/keys`** 打印完整报告：检测到的终端、发现的绑定数量，以及每个冲突对应的确切 `[keybindings]` 配置字段。`/keys refresh` 强制重新扫描机器（否则复用最多一天前的缓存快照）。
- **启动通知。** 启动时，如果冲突集合自上次警告以来*发生了变化*，jcode 显示一次性的提示，指向 `/keys`。它按冲突集合的签名去抖，因此用户每种不同的冲突集合只被警告一次，不会每次启动都被唠叨。

## 解决冲突

报告会点名冲突的 jcode 动作及其配置字段，例如：

```
  ⚠ Ctrl+Tab
      jcode: Switch to next model (keybindings.model_switch_next = "ctrl+tab")
      taken by terminal: next_tab
```

修复方式二选一：

- 在 `~/.jcode/config.toml` 的 `[keybindings]` 下重新绑定 jcode 动作（例如 `model_switch_next = "ctrl+shift+m"`），或
- 在终端或操作系统设置中更改冲突的快捷键。

## 实现

所有逻辑位于 `crates/jcode-setup-hints/src/keymap/`：

- `chord.rs` - `KeyChord`，一个归一化的 `(cmd/ctrl/alt/shift + key)`，统一各来源不同的按键拼写，加上用于解析 jcode 自身绑定字符串语法的 `KeyChord::parse`。
- `macos_hotkeys.rs` - 解码 `com.apple.symbolichotkeys` 的 `[ascii, keycode, modmask]` 三元组（纯逻辑 + 一个薄的子进程包装）。
- `terminal.rs` - 解析 `ghostty +list-keybinds` 输出（纯逻辑 + 包装）。
- `source.rs` - `DiscoveredBinding` 及其 `KeySource`。
- `conflicts.rs` - 将 `KeybindingsConfig` 枚举为和弦，与快照 diff，产生绑定到配置字段的 `Conflict`。`conflict_signature` 产生用于启动去抖的稳定签名。
- `report.rs` - 渲染人类可读的报告和紧凑状态行。
- `mod.rs` - `collect_snapshot` / `refresh_and_save` / `snapshot_cached_or_refresh`（持久化到 `~/.jcode/keymap-snapshot.json`）。

纯解析/解码/diff 函数经过单元测试，不触碰机器；只有 `read_*` 包装会派生子进程。

## 添加终端适配器

1. 在 `terminal.rs`（或同级模块）添加 `read_<terminal>_keybinds()`，产生带 `source: KeySource::Terminal` 的 `Vec<DiscoveredBinding>`，保持解析器纯净、子进程/文件读取薄。
2. 在 `mod.rs` 的 `collect_snapshot()` 中调用它，最好按检测到的终端门控，这样就不会为不存在的工具派生子进程。
3. 使用示例配置/输出文本为解析器添加单元测试。
