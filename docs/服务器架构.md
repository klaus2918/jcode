## 概述

jcode 使用**单服务器、多客户端**架构。一个服务器进程
管理所有会话和状态；TUI 客户端通过 Unix 套接字连接，
在断开或服务器重载后可透明重连。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                             服务器（🔥 blazing）                              │
│                                                                             │
│  jcode serve                                                                │
│  ├── Unix 套接字：  /run/user/$UID/jcode.sock                                │
│  ├── 调试套接字：  /run/user/$UID/jcode-debug.sock                          │
│  ├── 注册表：      ~/.jcode/servers.json                                    │
│  ├── 提供商（Claude/OpenAI/OpenRouter）                                     │
│  ├── MCP 池（跨会话共享）                                                   │
│  └── 会话：                                                                  │
│        ├── 🦊 fox   (active)  → "🔥 blazing 🦊 fox"                         │
│        ├── 🐻 bear  (active)  → "🔥 blazing 🐻 bear"                        │
│        └── 🦉 owl   (idle)    → "🔥 blazing 🦉 owl"                         │
└─────────────────────────────────────────────────────────────────────────────┘
         │              │              │
         ▼              ▼              ▼
    ┌─────────┐   ┌─────────┐   ┌─────────┐
    │ 客户端 1 │   │ 客户端 2 │   │ 客户端 3 │
    │ 🦊 fox  │   │ 🐻 bear │   │ 🦉 owl  │
    └─────────┘   └─────────┘   └─────────┘
```

## 命名

```
服务器 = 形容词/动词修饰词              会话 = 动物名词
────────────────────────────              ────────────────────────
🔥 blazing   ❄️ frozen   ⚡ swift          🦊 fox    🐻 bear   🦉 owl
🌀 rising    🍂 falling  🌊 rushing        🌙 moon   ⭐ star   🔥 fire
✨ bright    🌑 dark     💫 spinning       🐺 wolf   🦁 lion   🐋 whale

组合："🔥 blazing 🦊 fox" = 服务器 + 会话
```

服务器启动时获得一个随机的形容词/动词名称（例如 "blazing"）。
每个会话获得一个动物名词（例如 "fox"）。它们共同形成
在 UI 中显示的自然短语："🔥 blazing 🦊 fox"。

服务器名称通过注册表（`~/.jcode/servers.json`）在重载后持久。
当服务器在 `/reload` 时 exec 进入新二进制，新进程以新名称注册。
过时条目自动清理。

## 生命周期

```
  开始                            连接                        重载
  ─────                            ───────                     ──────
  jcode（首次运行）               jcode（后续）               /reload
       │                              │                          │
       ├─▶ 无服务器？派生守护进程     ├─▶ 服务器存在？           ├─▶ 服务器 exec 进入
       ├─▶ 等待套接字               │   直接连接               │   新二进制（同 PID）
       ├─▶ 作为客户端连接            │                          ├─▶ 所有客户端断开
       └─▶ 创建会话                 └─▶ 创建/恢复会话          └─▶ 客户端自动重连
```

### 服务器启动

当你运行 `jcode` 时，它检查服务器是否已在运行：

1. **服务器存在**：作为客户端直接连接
2. **无服务器**：以分离守护进程（`setsid`）派生 `jcode serve`，
   等待套接字，然后连接

服务器通过 `setsid()` 与派生的客户端完全分离，因此杀死
任何客户端都不会影响服务器或其他客户端。

长期部署可以用 `jcode serve --server-name <name>` 或
`JCODE_SERVER_NAME` 环境变量给守护进程一个稳定的客户端可见身份。
可选的环境变量 `JCODE_SERVER_DISPLAY_NAME` 也被接受，
供偏好面向显示名称的服务管理器使用。CLI 输入优先于环境输入。
名称被规范化为注册表安全的小写标签，因此
`mount-cloud/fabian` 显示为 `mount-cloud-fabian`。

### 服务器关闭

服务器在以下情况关闭：
- **空闲超时**：5 分钟无客户端连接（可配置）
- **手动**：服务器进程被杀死
- **重载**：服务器 exec 进入新二进制（同套接字路径）

### 远程客户端工作目录

默认情况下，客户端在订阅时将当前工作目录发送给服务器，
服务器将其用作会话工作目录。面向远程守护进程的套接字
转发包装器可以用 `--remote-working-dir` 保持客户端和服务器路径分离：

```bash
jcode --socket /tmp/jcode.sock -C /local/checkout --remote-working-dir /remote/checkout
```

`-C` 必须在客户端存在。`--remote-working-dir` 必须是
服务器上存在的绝对路径。

### 客户端重连

客户端有内置的重连循环。当连接断开时（服务器
重载、网络问题等）：

1. 客户端显示"连接丢失 - 重连中..."
2. 以指数退避重试（1 秒、2 秒、4 秒……最多 30 秒）
3. 重连后恢复同一会话（会话状态持久化在磁盘上）
4. 如果服务器已重载，客户端在有更新的客户端二进制可用时也可能重新 exec 自身

### 热重载（`/reload`）

1. 客户端向服务器发送 `Request::Reload`
2. 服务器向请求客户端发送 `Reloading` 事件
3. 服务器调用 `exec()` 进入带 `serve` 参数的新二进制
4. 新服务器进程在同一套接字上启动
5. 所有客户端自动重连
6. 发起客户端在其二进制过时时也会重新 exec

## 套接字路径

```
/run/user/$UID/
├── jcode.sock          # 主通信套接字
└── jcode-debug.sock    # 调试/测试套接字
```

## 自研模式

在 jcode 仓库内运行 `jcode` 时：

1. 自动检测仓库并启用自研模式
2. 连接到普通共享 jcode 服务器
3. 通过订阅元数据将该会话标记为 canary/自研
4. 仅对该会话启用自研提示词/工具
5. `/reload` 仍然热重载共享服务器，客户端重连

## 关键行为

| 场景 | 行为 |
|----------|----------|
| 首次 `jcode` 运行 | 派生服务器守护进程，连接 |
| 后续 `jcode` | 连接到现有服务器 |
| 杀死客户端 | 服务器 + 其他客户端不受影响 |
| `/reload` | 服务器 exec 新二进制，客户端重连 |
| 所有客户端关闭 | 服务器 5 分钟后空闲超时 |
| 恢复会话 | `jcode --resume fox` 重连到现有会话 |
