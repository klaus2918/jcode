# Jcode 桌面端构建计划

> 历史文档：本文描述已移除的旧版 `crates/jcode-desktop` 应用。当前桌面应用是 `crates/jcode-desktop2`。

状态：进行中的规划笔记
更新：2026-05-25

## 当前读解

Jcode Desktop 已经越过最初的空白画布原型。当前最强的线索是带本地 GitHub issue 浏览器/缓存和后台 `gh` 同步的单会话桌面表面。最近的工作增加了：

- issue 浏览器渲染器抽取
- issue 浏览器交互
- 本地 GitHub issue 缓存
- 后台 issue 同步 UI 状态
- issue 导航、调查提示注入、缓存排序和同步失败行为的测试

产品文档仍指向长期目标：键盘驱动、Niri 式的本地 AI 开发超级应用。正确的下一步不是直接跳到完整 IDE 或完整工作区管理器。从已验证的单会话表面向外构建，进入 issue 驱动的智能体工作流和可复用表面图元。

## 推荐产品顺序

### 1. 把 GitHub issue 工作流做到真正有用

这是近期最有价值的构建方向，因为它连接桌面 UI、仓库上下文、智能体启动和可操作的开发工作流。

接下来构建：

1. Issue 同步打磨
   - `gh` 缺失或未认证时显示可见的认证/安装引导
   - 浏览器中浮出同步时间戳和缓存路径
   - UI 中手动刷新快捷键帮助
   - 有界的后台同步状态，不会看起来卡住
2. Issue 过滤和分诊
   - 按标签/状态/文本过滤
   - 快速优先级覆盖持久化在 `local_overrides` 中
   - 隐藏/完成/本地忽略 issue 的交互
3. Issue 到智能体工作流
   - 从所选 issue 启动新会话
   - 注入结构化 issue 上下文、评论、标签和仓库事实
   - 可选派生实现智能体和审阅/检查智能体
4. Issue 活动循环
   - 显示与 issue 编号关联的运行中会话
   - 智能体行动后显示变更文件/测试状态
   - 从 issue 浏览器跳到相关会话

验证：

- `cargo test -p jcode-desktop issue --no-default-features`
- 假 `gh` runner 测试覆盖认证/缺失 CLI/评论失败
- 空、同步中、错误和窄宽度状态的 UI 快照/布局测试

### 2. 从单会话状态抽取通用表面/工作区图元

在 issue 工作流有了第一个具体的非聊天侧表面之后再做。避免投机性架构，但创建组合会话加 issue/活动表面所需的最小模型。

接下来构建：

1. `SurfaceId`、`SurfaceKind`、`SurfaceState`
2. 带水平列的一个通道
3. 左右焦点移动
4. 缩放/取消缩放聚焦表面
5. 按仓库/工作区持久化布局
6. 独立于渲染器的表面命令路由

从这些表面类型开始：

- `AgentSession`
- `GitHubIssues`
- `Activity`
- `DiffSummary` 或 `ChangedFiles`

验证：

- 焦点、移动、关闭、缩放和持久化的纯状态机测试
- 渲染器测试证明现有单会话表面仍无回归地组合
- 分离导航模式与文本输入模式的键盘路由测试

### 3. 构建活动/任务控制表面

桌面应用应擅长监督自主工作。活动应成为一等表面，而不是小状态面板。

接下来构建：

1. 流式显示当前会话状态、后台任务、工具运行和构建/测试任务
2. 按工作区/会话/issue/工具类型过滤
3. 选择活动项跳��到会话/工具输出
4. 醒目显示被阻塞的权限提示
5. 显示最近完成的验证结果

验证：

- 高容量更新的合成事件批量测试
- 空闲时无忙渲染循环
- 活动跳转到会话记录/工具卡片的测试

### 4. 添加级别 1 文件/diff 表面，而非完整编辑器

桌面需要审阅能力先于编辑能力。

接下来构建：

1. 变更文件列表
2. 只读文件预览
3. 只读统一 diff 预览
4. 在外部编辑器中打开路径/diff
5. 复制路径/片段
6. 把变更文件链接回会话/issue

验证：

- 大 diff/文件虚拟化测试
- 二进制/大文件回退
- 安全 mock 背后的外部打开命令测试

### 5. 命令面板和共享命令注册表

一旦有多个表面，命令面板应成为通用路由器。

接下来构建：

1. 桌面命令的命令注册表
2. 覆盖命令、会话、issue、文件和表面的模糊面板
3. 从同一注册表的键盘快捷键发现
4. 带安全确认分类的面板动作

验证：

- 注册表唯一性测试
- 模糊排序测试
- 所有可见快捷键都由已注册命令生成

## 下一批的显式非目标

暂不构建这些：

- 完整代码编辑器
- 插件/扩展系统
- 通用桌面窗口管理器行为
- 复杂的多窗口支持
- 超出解锁 issue 同步和模型/会话工作流所需的大型设置/认证 UI
- webview/Electron/Tauri 外壳

## 下一个具体实现切片

最好的即时切片是：

> 让 `/issues` 成为健壮的 issue 到智能体启动器。

完成定义：

1. 打开 `/issues` 立即加载缓存，并在适当时开始后台同步。
2. 空/错误状态解释如何安装/认证 `gh`。
3. 按下调查/启动键打开或派生带完整结构化 issue 上下文的真实会话。
4. issue 浏览器清晰显示同步状态、上次同步、评论获取失败和所选 issue 上下文。
5. 测试覆盖成功、缺失 `gh`、认证失败、同步部分失败、空缓存和窄布局。

这个切片足够小可以发布，但它把桌面应用推向其核心产品身份：issue 驱动的智能体任务控制。
