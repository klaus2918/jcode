# 模型能力架构

> 状态：已实现（P0），自 v0.64.2-dev 起
> 设计参考：DeepSeek-Reasonix 000-task docs 01/03（模型访问架构），适配到 jcode Rust 工作区。

jcode 的模型访问架构分层如下：

```text
config layer (jcode-config-types + jcode-base/config)
    |  NamedProviderConfig / NamedProviderModelConfig (capability fields)
    v
capability layer (jcode-provider-core::capability)
    |  ModelCapability + embedded registry + merge pipeline
    |  priority: explicit config > registry > heuristics > conservative default
    v
resolution layer (jcode-base provider/models + catalog_routes)
    |  ModelRoute capability projection (modalities/tools/reasoning/window/sampling)
    v
adapter layer (jcode-provider-*-runtime)
    |  Provider trait + optional capability interfaces
    v
runtime layer (jcode-app-core agent)
    |  tool gating, vision gating, effort, compaction, recovery
```

## 1. 能力模型（`jcode-provider-core/src/capability.rs`）

`ModelCapability` 是声明式模型能力的单一事实来源：

- `chat: bool`
- `modalities: Vec<Modality>`（`text` 是隐式的；`image`/`audio` 是叠加的）
- `reasoning: ReasoningCapability`（`protocol`、`efforts`、`default_effort`、`round_trip`、`tool_call_replay`、`thinking_kind`）
- `tools: Option<bool>`（`None` = 未知 -> 工具可用）
- `context_window` / `output_window`
- `sampling: SamplingCapability`（`temperature_supported`、`fixed_sampling`、`output_limit_field`）

内嵌的 `EMBEDDED_REGISTRY` 是一个 `const` 的 `RegistryEntry` 值表（精确 id 加上 `claude-*`/`gpt-5*` 前缀条目，可选按提供商键限定）。条目种子镜像之前的启发式输出，因此注册表本身不改变行为；它添加启发式无法表达的字段（视觉、工具、采样、推理往返标志）。

## 2. 解析优先级

每个能力决策都经过 `resolve_capability_with_context_fn`（或用于提供商核心默认启发式的 `resolve_capability`）：

```text
1. explicit config : NamedProviderModelConfig fields / input modalities
2. embedded registry: EMBEDDED_REGISTRY match (exact > prefix, provider-scoped)
3. heuristics      : open-weight context families, reasoning ladders, vision names
4. conservative default: text-only, tools available, no reasoning control
```

`ResolvedModelCapability` 携带 `CapabilityTrace`，记录每个字段的获胜来源（`config` / `registry` / `heuristic` / `default`），用于诊断。

## 3. 配置面（`jcode-config-types`）

`[providers.<name>.models]` 下的按模型覆盖：

```toml
[[providers.my-gateway.models]]
id                   = "custom-vlm"
context_window       = 128000
input                = ["text", "image"]
vision               = true            # explicit visual capability
tools                = false           # never send tool definitions
reasoning_protocol   = "openai"        # auto|deepseek|openai|thinking_type|anthropic|none
supported_efforts    = ["low", "high"] # /effort ladder
default_effort       = "high"          # /effort auto target
output_window        = 16384
temperature_supported = false          # fixed-sampling backends
fixed_sampling       = true
output_limit_field   = "max_completion_tokens"
```

所有字段可选且有别名（`context_limit`、`supports_vision`、`efforts`、`reasoning-protocol` 等）；旧配置原样解析。

## 4. 路由投影

`ModelRoute` 增加可选 `capability: Option<RouteCapabilityView>`（serde `skip_serializing_if`），因此远程客户端和模型选择器可以在不触碰凭据或端点的情况下看到声明的能力。只携带保守默认的视图被省略，保持线上字节稳定。

`jcode model list --json` 为每个路由包含能力视图；`jcode model list --verbose` 打印人类可读的能力块。

## 5. 门控

- **工具门控**：智能体回合调用 `gated_tool_definitions()`，当活动模型解析为 `tools == false`（显式配置或注册表）时清空工具集。未知模型保留工具（无行为变化）。
- **视觉门控**：`capability.modalities` 为支持图像的模型包含 `image`；运行时保留现有图像处理。
- **采样**：`SamplingCapability` 泛化 Kimi K3 固定采样约束；显式 `temperature_supported`/`fixed_sampling`/`output_limit_field` 字段馈入路由视图。

## 6. 接入新模型

### 相同协议，新供应商/模型（最常见）

1. 在 `[providers.<name>]` 下添加/验证端点，带 `api_key_env`（绝不把密钥粘进 TOML）。
2. 在 `[[providers.<name>.models]]` 下声明模型及其能力字段。
3. 如果模型不需要显式覆盖，添加内嵌注册表条目（或等启发式覆盖它）。
4. 用 `jcode model list --json`（路由能力）和一次实时回合验证。

### 新供应商类型（新线上协议）

1. 添加格式 crate（`jcode-provider-<name>`）和实现 `Provider` 的运行时 crate（`jcode-provider-<name>-runtime`）。
2. 在 `src/cli/startup.rs` 中与现有外部运行时一起注册该运行时。
3. 在运行时中添加线上形态的推理/努力处理；当它是已知形态时在注册表中声明协议。
4. 在 `jcode-base/src/provider/catalog_routes.rs` 中添加路由构建，在认证层添加凭据/认证处理。
5. 添加镜像 `jcode-provider-openai-runtime` / `jcode-provider-anthropic-runtime` 覆盖的测试（请求构造、SSE、工具流、错误映射、重试）。
6. 在本文件和提供商元数据目录（`jcode-provider-metadata`）中记录端点和模型。

## 7. 兼容性保证

- 新配置字段可选且有别名；旧 TOML 原样加载。
- `ModelRoute.capability` 为空/默认时跳过；旧客户端忽略未知字段。
- 注册表只影响*默认*解析；显式配置总是优先。
- 凭据、端点或代理数据永远不会进入 `ModelCapability` 或 `RouteCapabilityView`；两者都安全地发送给远程客户端。
