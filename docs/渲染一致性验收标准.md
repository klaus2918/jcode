# 渲染核心一致性：验收标准、阈值与统计报告

状态：已采用用于 `jcode-render-core` -> TUI 切换。
工具框架：`crates/jcode-tui-markdown/src/render_core_adapter_tests.rs`
（比较 `render_markdown_via_core*` 与旧版 `render_markdown*` 流水线的差分测试）。

## 1. 一致性级别（测量什么）

每个级别都是不同的、机器可检查的比较函数。只有当测试直接断言它时，级别才算被覆盖。

| 级别 | 定义 | 比较器 | 测试 |
|-------|------------|------------|-------|
| L1：内容一致性 | 空白折叠后的可见文本相同 | `flattened()` | `parity_*`、`fuzz_visible_text_parity`、`fuzz_random_documents_parity` |
| L2：行结构一致性 | 每行修剪后的非空可见文本相同（捕获换行分歧） | `nonblank_texts()` | `fuzz_random_documents_line_structure` |
| L3：包裹布局一致性 | 生产包裹在宽度 {20, 40, 80} 后的 L2 比较 | 对包裹输出的 `nonblank_texts()` | `fuzz_random_documents_wrapped_parity` |
| L4：样式不变量 | 定向样式等价：数学前景跨度相同、粗体携带 BOLD、行内代码携带背景填充、标题按级别着色、显示数学加框 | 跨度级谓词 | `probe_math_divergence`、`core_marks_bold_and_code_styling`、`core_renders_display_math_frame` 等 |

刻意排除在范围外（记录的分歧，不是失败）：空行填充计数、装饰标记字形选择，以及非不变量跨度上的精确 `Style` 相等。任何新的有意分歧必须列在这里。

## 2. 验收阈值

所有差分测试**零容忍**：每个级别、每个层级的验收标准都是 `mismatches == 0`。没有"可接受的失配率"；下面的统计量化一次通过运行*证明*了残余失配概率的什么，而不是我们容忍什么。

| 层级 | 每个模糊套件的迭代次数 | 门 | 残余失配率上界（95%，三规则：p < 3/N） |
|------|---------------------------|------|--------------------------------------------------|
| CI（默认） | 5000（L1、L2），3000×3 宽度 = 9000 次渲染（L3） | 每个触碰 `jcode-tui-markdown`、`jcode-render-core` 的 PR 必须通过 | 每个生成文档 p < 6.0e-4（L1/L2）；每个文档每宽度 p < 1.0e-3（L3） |
| 切换前深度运行 | `JCODE_MD_FUZZ_ITERS=100000` | 必须通过一次，在提议切换的确切提交上 | 每个生成文档 p < 3.0e-5 |
| 夜间（可选浸泡） | `JCODE_MD_FUZZ_ITERS=25000`，轮换 `JCODE_MD_FUZZ_SEED`（如纪元日） | 失败用复现种子记录 issue | 跨种子随时间累积覆盖 |

上界理由：N 个独立同分布生成文档、0 个观察失配时，失配概率的单侧 95% 置信上界是 `1 - 0.05^(1/N) ≈ 3/N`（"三规则"）。

固定语料标准（非统计、穷举）：

- `fuzz_visible_text_parity` 语料中的每个条目（当前 43 个用例）通过 L1。向生成器添加构造**要求**至少为它添加一个固定语料用例，使回归可定位。
- 每个 `parity_*` 单元用例通过 L1。每个 L4 不变量测试通过。

切换门（全部必需）：

1. 切换提交上 CI 层级绿色。
2. 深度运行（10 万次迭代）对 L1、L2 和 L3 绿色。
3. 用第二个种子（任何与默认不同的值）重复深度运行绿色，减少特定种子盲区。
4. 生成器覆盖清单（第 4 节）没有旧版渲染器支持的未勾选构造。

## 3. 统计报告要求

每个模糊测试都已实现且必须保留此失败报告契约：

- **可复现性：** 每次失败报告迭代索引 `i`；每次迭代的 RNG 推导为 `seed = base_seed + i * 0x100000001B3`，因此任何单次失败都可用 `JCODE_MD_FUZZ_SEED=<base_seed> JCODE_MD_FUZZ_ITERS=<i+1>` 复现（或重新推导单个种子）。`base_seed` 默认是每个套件的固定常量，可通过 `JCODE_MD_FUZZ_SEED` 覆盖。
- **有界失败转储：** 在中止循环前收集最多 5 个失败用例，然后在一条断言消息中报告全部（输入文档、核心输出、旧版输出）。绝不在第一个用例就失败；分类分歧需要多个示例。
- **全输入回显：** 原始 markdown 输入逐字打印，使失败用例可以直接提升进固定语料。

为切换决策报告结果时（手动或脚本摘要，如 PR 描述中）必需添加：

- `iters`、`base_seed`、套件名，以及每个级别（L1-L4）的通过/失败。
- 每个通过的模糊套件的隐含 95% 上界 `3/N`。
- 开发中发现的任何失败：一行分类（解析器分歧、适配器样式、包裹分歧、生成器产物）以及为固定修复添加的语料用例。

## 4. 生成器覆盖清单

统计上界只覆盖生成器的分布。生成器（`gen_block`/`gen_inline`）必须覆盖，且每当任一渲染器添加构造时审计清单：

- [x] 标题（1-3）、段落、硬/软换行
- [x] 粗体、斜体、删除线、行内代码、链接
- [x] 行内数学、显示数学、货币美元消歧
- [x] 有序/无序/嵌套/任务列表、定义列表
- [x] 块引用（嵌套、多行）、主题分隔
- [x] 围栏代码块（带/不带语言）、表格（1-3 列）
- [x] 脚注、CJK/emoji 文本
- [ ] setext 标题（仅固定语料，不在生成器中）
- [ ] 图像、自动链接、HTML 片段（仅固定语料）
- [ ] 引用风格链接、缩进代码块（未覆盖）

未勾选项必须要么添加到生成器，要么在切换 PR 中显式豁免，并带演示一致性的固定语料用例。

## 5. 运行

```sh
# CI 等价（所有级别，默认迭代）
cargo test -p jcode-tui-markdown --lib render_core_adapter

# 深度运行（切换门；XPS 13 上约 80 秒）
JCODE_MD_FUZZ_ITERS=100000 \
  cargo test -p jcode-tui-markdown --lib render_core_adapter::tests::fuzz

# 替代种子确认
JCODE_MD_FUZZ_ITERS=100000 JCODE_MD_FUZZ_SEED=20260713 \
  cargo test -p jcode-tui-markdown --lib render_core_adapter::tests::fuzz
```
