# 消息语气指南

jcode 在系统/状态消息中（TUI 通知、CLI 输出、通知）如何与用户对话。目标：直接向用户说明发生了什么以及我们为他们做了什么，而不是叙述内部机制。

## 核心原则

1. **用用户的语言先讲发生了什么。**
   用户关心的是结果（"你的智能体没有完成工作"），而不是机制名称（"todo 完成门控"、"自动催促已武装"、"排队续作"）。

2. **用过去时说明我们为他们做了什么。**
   当工具框架自动执行操作时，将其表述为已经处理完成："我们已为你催促它。"而不是"自动催促中……"（进行时、以机器为中心）或"催促已排定"（配置术语）。

3. **逃生出口放最后，保持简短。**
   控件和退出选项放在人类语句之后："。使用 /poke off 停止。"绝不把标志或设置名称放在开头。

4. **面向用户的文本中不要出现内部术语。**
   应避免的词："gate（门控）"、"armed（武装）"、"dispatch（派发）"、"continuation（续作）"、"followup（跟进）"、"queued dispatch（排队派发）"、"state（状态）"、"flag（标志）"。内部名称可以出现在日志、注释和代码中，但不能出现在用户阅读的内容里。

5. **用完整句子而非标签。**
   优先"你的智能体带着 5 个未完成的 todo 停止了。"而不是"自动催促：5 个未完成 todo。"

6. **警告先解释后果，再说该怎么做。**
   "我们停止了催促，因为它没有取得进展。请检查剩余的 todo。"而不是"在 N 次尝试后门控耗尽。"

## 公式

> [发生了什么。] [我们做了什么。] [如何改变这一行为。]

除第一部分外，各组成部分都可选，但顺序保持不变。

## 示例

| 之前 | 之后 |
|---|---|
| `👉 Auto-poking: 5 incomplete todos. /poke off to stop.` | `👉 5 个未完成 todo。我们已为你催促。使用 /poke off 停止。` |
| `Auto-poking: todos complete; sending confidence summary follow-up.` | `Todo 已完成。正在请智能体做最终信心确认。` |
| `⚠️ Todo completion gate: validation still failing after repeated nudges. Auto-poke stopped; review the remaining todos manually.` | `⚠️ 我们催促了智能体几次，但它停止了进展。已放弃；请自行检查剩余 todo。` |

## 非目标

- 日志行、追踪和调试输出保留精确的内部名称。
- 面向开发者的错误消息（panic、内部错误）不在范围内。
