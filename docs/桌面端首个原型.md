# 桌面端首个原型目标

> 历史文档：本文描述已移除的旧版 `crates/jcode-desktop` 应用。当前桌面应用是 `crates/jcode-desktop2`。

状态：提案
更新：2026-04-25

Jcode Desktop 的第一个实现步骤应该是**阶段 0：一个全屏的空白白色画布**。

不要从以下开始：

- 伪造的工作区表面
- 真实服务器集成
- 完整编辑器
- 任何浏览器工作
- 设置/认证流程
- 打包
- 完美的文本渲染

先证明绝对基础：

> 一个带自定义 GPU 渲染白色画布的原生全屏窗口。

## 阶段 0 必须证明什么

1. 原生窗口在 Linux 上打开。
2. 应用通过 `--fullscreen` 支持全屏或无边框全屏模式。
3. 应用创建 GPU 表面。
4. 应用把表面清成白色。
5. 应用处理大小/缩放因子变化而不崩溃。
6. 应用用 `Esc` 或关闭窗口干净退出。
7. 应用使用按需事件循环，而不是忙渲染循环。
8. 应用可以独立于 TUI 构建和运行。

## 为什么这先于空间工作区

空白画布刻意很小。它在增加产品复杂性之前验证平台/渲染基础。

它回答：

- 我们能干净地创建桌面 crate 吗？
- `winit` 作为初始平台外壳有效��？
- `wgpu` 能在 Linux 开发机上初始化吗？
- 我们能在没有 web 视图或 UI 框架的情况下渲染一帧吗？
- 全屏行为能尽早测试吗？

## Linux 桌面入口

仓库包含一个面向安装的桌面入口：

```text
packaging/linux/jcode-desktop.desktop
```

它期望 `jcode-desktop` 二进制在 `PATH` 上可用。安装或把二进制复制到你的桌面启动器可执行的位置后进行本地测试，把入口复制到你的用户应用目录：

```bash
mkdir -p ~/.local/share/applications
cp packaging/linux/jcode-desktop.desktop ~/.local/share/applications/
update-desktop-database ~/.local/share/applications 2>/dev/null || true
```

## 此后的阶段 1 目标

阶段 0 可行后，下一个原型是伪造数据的空间工作区。第一个切片应在真实会话或文本渲染之前证明核心 Niri/Vim 风格交互模型：

```text
导航模式：
  h/l          在当前工作区内聚焦列
  j/k          移动到下方/上方的工作区
  H/L          把聚焦的列向左/右移动
  J/K          把聚焦的列移动到下方/上方的工作区
  n            创建伪造会话表面
  Ctrl+;       创建伪造会话表面
  Ctrl+?       打开/聚焦热键帮助
  Ctrl+1       偏好 25% 屏宽的的面板
  Ctrl+2       偏好 50% 屏宽的面板
  Ctrl+3       偏好 75% 屏宽的面板
  Ctrl+4       偏好 100% 屏宽的面板
  x            关闭聚焦的表面
  z            缩放/取消缩放聚焦的表面
  i 或 Enter   进入插入模式
  Esc          退出原型

插入模式：
  输入          捕获为草稿输入
  Esc           返回导航模式
```

初始渲染器可以使用原始彩色/圆角图元加上一个微小的内置位图字体，用于早期状态和面板标签。正确的字体渲染可以在工作区行为感觉对之后再做。视觉方向应把颜色放在柔和静态的蓝/薰衣草/薄荷渐变背景上，面板透明叠在上面，状态颜色柔和，一个很细的灰色聚焦环，以及可见但低调的未聚焦边框。紧凑的状态栏应放在顶部，而不是底部。在真实文本/装饰有用之前，单个面板不应有自己的顶部标题栏。面板应填满大部分可用空间，只有窄间距和略微圆角。面板数量应同时适应当前桌面应用窗口大小和用户选择的偏好面板大小：`Ctrl+1` 偏好 25% 屏宽面板，`Ctrl+2` 偏好 50%，`Ctrl+3` 偏好 75%，`Ctrl+4` 偏好 100%。带 `Ctrl+1` 的全屏应用可以显示四列，而带 `Ctrl+4` 的全屏只显示一列。25% 屏宽的应用程序窗口无论预设如何都只显示一列，因为只能容纳一个偏好的四分之一屏面板。布局方向是 Niri 式的：每个工作区是一个垂直通道，包含一个水平可滚动的全高列条。列绝不应在同一个工作区内堆叠。顶部状态栏应包含左侧的活动工作区编号、居中的扁平 Waybar 式预览条，以及右侧的模式/面板大小文本。在预览条中，附近的工作区显示为紧凑的水平组，每个面板是一个彩色刻度/块，非活动工作区变暗，活动工作区组高亮，聚焦面板最强，可见水平视口被勾勒。平滑的视口/相机动画应使聚焦、工作区、派生/关闭和面板大小变化可读，而不是瞬间传送：`h/l` 和 `Ctrl+1` 到 `Ctrl+4` 水平动画，`j/k` 工作区变化垂直滑动……

阶段 1 证明真正的产品赌注：

- 多个可见的智能体会话
- Niri 式空间布局
- `h/l` 列导航和 `j/k` 工作区导航
- 移动/关闭/缩放表面
- 独立的伪造记录
- 活动表面
- 自定义渲染性能
- 接近零的空闲 CPU

## 初始阶段 1 表面种类

```rust
enum SurfaceKind {
    AgentSession,
    Activity,
    WorkspaceFiles,
    Diff,
    Debug,
}
```

没有浏览器预规划。还没有完整编辑器。

## 阶段 1 成功标准

当用户能启动它、看到多个伪造会话、用 leader+`h/j/k/l` 在它们之间移动、创建/移动/关闭/缩放表面，并确认应用保持流畅和空闲高效时，伪造工作区原型即成功。
