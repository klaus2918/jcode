## 本 fork 与 upstream 的差异（读文档前先知道）

本仓库是 upstream 的功能减法 fork：保留核心工作方式（单服务器 + 多客户端、TUI 优先、
智能体回合循环、记忆、集群、自研），移除了大量外围能力。**以下能力在本仓库代码中不存在**，
因此没有任何文档描述它们：

- 仓内桌面端 GUI（桌面端系列文档已随能力一并删除）
- 浏览器工具与 `computer`（macOS 计算机使用）
- 遥测上报链路
- 赞助商与发现（discovery）转化链路
- 云同步、iOS 客户端
- 登录 / 账户层命令与内置第三方 provider 预设（模型接入改为配置驱动，见[模型接入](模型接入.md)）
- PDF、无人值守（overnight）、邮件通知
- 全局热键与键位冲突检测
- Harness API / SDK
- 在线自更新（`jcode update` 仅本地包与源码重建）

完整的移除清单与依据见 [README](../README.md) 第一节。

## 文档约定

- 描述**当前行为**的文档直接放在 `docs/` 顶层。
- **不再区分 `plans/`、`audits/`、`proposals/`、`dev/` 子目录**：这些目录下的历史计划、
  时点审计与未落地提案，有价值的部分已并入上述 16 篇（并在正文中标注「设计意图/未实现」），
  其余已删除。需要看历史材料时用 git 历史。
- 文档中引用的 crate 名、文件路径、斜杠命令、CLI 子命令、配置键必须与代码一致；
  改代码时同步改文档。
- 以「现状」口吻书写的段落必须在本仓库代码中可验证；纯设计意图必须显式标注
  「设计意图」「未实现」「待办」。
- 被精简删除的能力不要在文档里以现状口吻出现。
- 仓库根目录只放 README、AGENTS、LICENSE 等元文件，其他内容都在 `docs/`。
