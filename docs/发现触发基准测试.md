# 发现触发基准测试

`scripts/benchmark_discovery.py` 测量普通用户请求是否会让 Jcode 浏览预期的赞助发现类别并在清单中收到特定工具。它还支持无发现对照组：如果智能体为不需要外部服务的任务浏览目录，则失败。

基准在浏览响应处停止。它不选择工具、不揭示设置说明、不创建账户、不安装软件，也不执行任何有后果的操作。

## 运行

为每个活动目录条目运行一次"重试直到命中"试验：

```bash
python scripts/benchmark_discovery.py
```

每个条目运行三次试验，每次试验最多允许五次模型尝试：

```bash
python scripts/benchmark_discovery.py --trials 3 --max-attempts 5
```

按用例 ID 或工具名运行一个用例：

```bash
python scripts/benchmark_discovery.py --case agentcard
python scripts/benchmark_discovery.py --case agentmail
python scripts/benchmark_discovery.py --case context-dev-website-enrichment
```

默认使用 Jcode 的常规工具集，让 Discovery 与内置浏览器、shell、网页和集成能力竞争。这是有代表性的泛化分数。使用 `--discovery-only` 做聚焦冒烟测试，在没有竞争工具的情况下测量类别和清单选择：

```bash
python scripts/benchmark_discovery.py --discovery-only --trials 3
```

报告默认写入 `target/discovery-benchmark/latest.json`。使用 `--output` 保留命名运行。

## 目录覆盖

调用模型之前，运行器获取 `DISCOVERY_CATEGORIES` 中声明的每个类别。每个活动的 `category/tool` 对必须在 `scripts/discovery_benchmark_cases.json` 中至少有一个正用例。一个工具可以有多个场景，无发现对照组不参与目录覆盖。如果新清单没有正用例，或移除的清单留下过时的正用例，运行失败。

不调用模型验证覆盖：

```bash
python scripts/benchmark_discovery.py --dry-run
```

离线运行器测试，传入保存的类别到清单 JSON 文件：

```bash
python scripts/benchmark_discovery.py \
  --catalog-file /path/to/catalog.json \
  --dry-run
```

`--allow-catalog-mismatch` 可用于调查，但已发布的基准结果应使用严格覆盖。

## 指标

每个用例报告：

- 成功的重试直到命中试验；
- 首次尝试预期成功，使重试无法掩盖弱触发；
- 首次尝试预期工具到达，包括跟踪的直接选择；
- 收到预期清单所需的尝试次数；
- 到成功的 `discover_tools` 浏览结果的时间；
- 命中前的错误类别 Discovery 调用；
- 绕过浏览与比较阶段的直接选择调用；
- 无发现对照组中的意外 Discovery 调用；
- 空清单、请求失败、超时和有界的 stderr 上下文；
- 运行时混淆的未命中（不成功的尝试也遇到外部工具或进程错误），与干净的模型未命中分开保存；
- 精确的提示词、模型、工具模式、活动目录和基准配置。

命中要求预期类别的浏览响应包含预期工具。直接选择响应不算命中，但它被单独记录，使报告能区分错过的触发与未经浏览类别就选择的供应商。运行器在该尝试中立即停止，在模型可以按设置说明行动之前。

无发现对照组只有在模型未调用 `discover_tools` 就成功完成时才通过。任何 Discovery 调用都是误报，无论类别或清单内容如何。对照组从不重试，因此误报不会被之后的一次干净尝试掩盖。

## 基准流量标记

运行器使用专用 Jcode 服务器，带：

```text
JCODE_DISCOVERY_BENCHMARK=1
```

来自该服务器的每个 Discovery 请求都携带：

```text
x-jcode-discovery-benchmark: 1
```

Discovery 遥测携带：

```json
{"benchmark_run": true}
```

遥测工作者在 `discovery_details.benchmark_run` 中存储并索引该标志。发现服务应在其日志中保留请求头，使基准请求也能从赞助商、计费和自然使用报告中排除。

## 用例设计

用例必须是自然请求。不要包含：

- 预期工具名；
- `discover_tools` 或使用 Discovery 的说明；
- 作为实现提示的预期类别；
- 从赞助商清单复制的设置命令。

正提示词应描述使外部能力成为必需的用户结果。对照组应类似相邻的任务但不需要该能力，例如起草邮件内容或编辑邮件模板而不发送。保持提示词在提示词调优实验中稳定。只有在用户场景无效时才更改用例，而不是为了挽救失败的分数。

添加或移除目录条目时，在同一变更中更新 `scripts/discovery_benchmark_cases.json`，并为完整目录运行至少一次实时试验。
