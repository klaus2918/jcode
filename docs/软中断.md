# 软中断：无缝消息注入

## 概述

软中断允许用户在不取消当前生成的情况下向正在进行的 AI 对话注入消息。取代了破坏性的"取消-重启"流程：消息被排队，并在模型提供商连接空闲的安全点自然合入。

## 当前行为（硬中断）

```
AI 处理期间用户输入消息
         │
         ▼
    ToolDone 事件
         │
         ▼
    remote.cancel()  ← 取消当前生成
         │
         ▼
    等待 Done 事件
         │
         ▼
    将用户消息作为新请求发送
         │
         ▼
    AI 重新开始
```

**问题：**
- 丢失 AI 正在做的部分工作
- 取消完成前的延迟
- 新 API 调用时全文重发上下文
- 突兀的用户体验

## 新行为（软中断）

```
AI 处理期间用户输入消息
         │
         ▼
    消息存入 soft_interrupt 队列
         │
         ▼
    AI 继续处理...
         │
         ▼
    到达安全注入点
         │
         ▼
    消息追加到对话历史
         │
         ▼
    AI 在下一轮循环自然看到它
```

**好处：**
- 不取消、不丢工作
- 无延迟
- AI 自然合入用户输入
- 流畅的用户体验

## 安全注入点

关键约束是：**我们只能在未从模型提供商积极流式传输时注入**。智能体循环有几个自然的暂停点：

### 智能体循环结构（src/agent.rs）

```rust
loop {
    // 1. 构建消息并调用 provider.stream()
    // === 此处提供商拥有连接 ===
    // 流事件：TextDelta、ToolStart、ToolInput、ToolUseEnd

    // 2. 流结束

    // 3. 将助手消息加入历史
    // （必须在注入前完成，以保持缓存和对话顺序）

    // 4. 检查是否存在工具调用
    if tool_calls.is_empty() {
        // ═══════════════════════════════════════════════
        // ✅ 注入点 B：无工具，回合完成
        // ═══════════════════════════════════════════════
        break;
    }

    // 5. 执行工具并添加 tool_results
    for tc in tool_calls {
        // 执行单个工具...
        // 将结果加入历史...

        // ═══════════════════════════════════════════════
        // ✅ 注入点 C：工具执行之间
        // （仅用于紧急中止 - 必须先添加跳过的 tool_results）
        // ═══════════════════════════════════════════════
    }

    // ═══════════════════════════════════════════════
    // ✅ 注入点 D：所有工具完成，下次 API 调用之前
    // ═══════════════════════════════════════════════

    // 循环继续 → 下一次 provider.stream() 调用
}
```

### 关键 API 约束

**Anthropic API 要求每个 `tool_use` 块必须紧跟其对应的 `tool_result` 块。** 任何用户文本消息都不能注入到
`tool_use` 与它的 `tool_result` 之间。

这意味着我们不能注入消息：
- 在包含 tool_use 块的助手消息之后
- 在所有 tool_results 添加完成之前

### 注入点详情

| 点 | 位置 | 时机 | 用例 |
|-------|----------|--------|----------|
| **B** | 回合完成 | 未请求工具 | 安全：无需配对的 tool_use 块 |
| **C** | 工具循环内部 | 仅紧急中止 | 必须先添加桩 tool_results |
| **D** | 所有工具之后 | 下次 API 调用之前 | **默认**：最安全的注入点 |

**重要**：我们不在非紧急中断时于工具之间注入。那样会把用户文本放在 tool_results 之间，可能违反 API 约束。所有非紧急注入都推迟到 D 点。

### 点 B：回合完成（无工具）

```
时间线：
  提供商：TextDelta... [流结束，无工具调用]
  智能体：──► 在此注入 ◄──
  智能体：本会退出循环，但改为携带用户消息继续

AI 看到："我完成了回答，用户有后续问题"
```

**最适合：** AI 仅回复文本时的快速追问。

### 点 C：工具之间

```
时间线：
  智能体：执行工具 1 → 结果 1
  智能体：──► 在此注入 ◄──
  智能体：执行工具 2 → 结果 2（或用户说"停止"则跳过）
  智能体：下次 API 调用

AI 看到："工具 1 结果、用户插话、工具 2 结果（或跳过消息）"
```

**最适合：**
- 紧急中止："等等，别执行其他工具"
- 执行中指导："下一个文件，还要检查 X"

### 点 D：所有工具之后

```
时间线：
  智能体：执行所有工具 → 收集全部结果
  智能体：──► 在此注入 ◄──
  智能体：下次 API 调用包含：[所有工具结果] + [用户消息]

AI 看到："我的所有工具已完成，用户补充了上下文"
```

**最适合：** 默认行为。最干净、最可预测。

## 实现

### 协议变更

为软中断添加新请求类型：

```rust
// src/protocol.rs
#[serde(rename = "soft_interrupt")]
SoftInterrupt {
    id: u64,
    content: String,
    /// 若为 true，可在 C 点中止剩余工具
    urgent: bool,
}
```

### 智能体变更

添加软中断队列并在每个注入点检查：

```rust
// src/agent.rs
pub struct Agent {
    // ... 现有字段
    soft_interrupt_queue: Vec<SoftInterruptMessage>,
}

struct SoftInterruptMessage {
    content: String,
    urgent: bool,
}

impl Agent {
    /// 检查并注入任何待处理的软中断消息
    fn inject_soft_interrupts(&mut self) -> Option<String> {
        if self.soft_interrupt_queue.is_empty() {
            return None;
        }

        let messages: Vec<String> = self.soft_interrupt_queue
            .drain(..)
            .map(|m| m.content)
            .collect();

        let combined = messages.join("\n\n");

        // 作为用户消息加入对话
        self.add_message(Role::User, vec![ContentBlock::Text {
            text: combined.clone(),
            cache_control: None,
        }]);
        self.session.save().ok();

        Some(combined)
    }

    /// 检查是否有应中止剩余工具的紧急中断
    fn has_urgent_interrupt(&self) -> bool {
        self.soft_interrupt_queue.iter().any(|m| m.urgent)
    }
}
```

### 注入点实现

```rust
// 在 run_turn_streaming / run_turn_streaming_mpsc 中

loop {
    // ... 从提供商流式传输 ...
    // ... 将助手消息加入历史 ...

    // 注意：如果存在工具调用，我们不能在此注入！
    // API 要求 tool_use → tool_result 之间不得有消息。

    if tool_calls.is_empty() {
        // 点 B：无工具，回合完成 - 可安全注入
        if let Some(msg) = self.inject_soft_interrupts() {
            let _ = event_tx.send(ServerEvent::SoftInterruptInjected {
                content: msg,
                point: "B".to_string(),
            });
            // 不退出 - 继续循环以处理注入的消息
            continue;
        }
        break;
    }

    // ... 工具执行循环 ...
    for (i, tc) in tool_calls.iter().enumerate() {
        // 在每个工具（首个除外）之前检查紧急中止
        if i > 0 && self.has_urgent_interrupt() {
            // 点 C：紧急中止 - 必须先添加跳过的 tool_results
            for skipped in &tool_calls[i..] {
                self.add_message(Role::User, vec![ContentBlock::ToolResult {
                    tool_use_id: skipped.id.clone(),
                    content: "[已跳过：用户中断]".to_string(),
                    is_error: Some(true),
                }]);
            }
            // 现在可以安全注入用户消息
            if let Some(msg) = self.inject_soft_interrupts() {
                let _ = event_tx.send(ServerEvent::SoftInterruptInjected {
                    content: msg,
                    point: "C".to_string(),
                });
            }
            break;
        }

        // ... 执行工具并添加 tool_result ...
    }

    // 点 D：所有工具完成后，可安全注入
    if let Some(msg) = self.inject_soft_interrupts() {
        let _ = event_tx.send(ServerEvent::SoftInterruptInjected {
            content: msg,
            point: "D".to_string(),
        });
    }
}
```

### TUI 变更

更新交错处理以使用软中断：

```rust
// src/tui/app.rs

// 不再：
//   remote.cancel() → 等待 → 发送消息

// 改为：
//   remote.soft_interrupt(message, urgent)

// 消息将在下一个安全点注入
// 不取消、不等待
```

### 反馈用的服务器事件

```rust
// src/protocol.rs
ServerEvent::SoftInterruptInjected {
    content: String,
    point: String,  // "A"、"B"、"C" 或 "D"
}
```

这允许 TUI 显示诸如"消息已在工具 X 之后注入"的反馈。

## 用户体验

### 默认模式（queue_mode = false）

```
处理期间用户按回车：
  → 消息进入软中断队列
  → 状态显示："⏳ 将在下一个安全点注入"
  → AI 继续工作...
  → [ToolDone] → 消息被注入
  → 状态显示："✓ 消息已注入"
  → AI 自然合入它
```

### 紧急模式（Shift+Enter 或特殊标志）

```
处理期间用户按 Shift+Enter：
  → 消息作为紧急软中断入队
  → 状态显示："⚡ 将尽快注入（可能跳过工具）"
  → AI 继续当前工具...
  → [ToolDone] → 跳过剩余工具，注入消息
  → AI 看到：工具 1 结果 + "用户中断，跳过了工具 2-3" + 用户消息
```

## 对比

| 方面 | 硬中断（当前） | 软中断（新） |
|--------|-------------------------|---------------------|
| 取消生成 | 是 | 否 |
| 丢失部分工作 | 是 | 否 |
| 延迟 | 有（等待取消） | 无 |
| API 调用 | 浪费部分调用 | 高效 |
| 用户体验 | 突兀 | 流畅 |
| 复杂度 | 简单 | 中等 |

## 边界情况

1. **多个软中断**：用 `\n\n` 分隔符合并为单条消息
2. **纯文本响应期间的软中断**：在 B 点注入，继续循环
3. **提供商内部处理工具**（Claude CLI）：仍然可用，注入发生在我们自己的循环中
4. **无工具的紧急中断**：按普通处理（没有可跳过的）
5. **流错误**：清空软中断队列，正常报告错误

## 测试

1. AI 流式传输文本（无工具）时发送消息 → 应在 B 点注入
2. AI 执行工具时发送消息 → 应在 D 点注入（所有工具之后）
3. 多个工具排队时发送紧急消息 → 应在 C 点跳过剩余工具
4. 快速连续发送多条消息 → 应合并为一次注入
5. 验证没有 tool_use/tool_result 配对的 API 错误
