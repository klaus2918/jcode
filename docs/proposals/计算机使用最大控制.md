# 路线图：`computer` 工具的 macOS 最大控制

目标：在平台允许的范围内，给智能体尽可能可靠的 macOS 控制能力，包括**不打扰用户当前所看的后台控制**。

这建立在 v1 `computer` 工具之上（PR #345）：截图、坐标鼠标/键盘、滚动、AX 树读取、光标、权限检查。

下面所有内容都可以用已在 lockfile 中或 crates.io 上可用的 crate 用 Rust 实现（`accessibility-sys`、`screencapturekit`、`objc2-app-kit`、`core-graphics`）。无 Swift/ObjC 构建步骤。

---

## 唯一硬约束

macOS 有一个**由整个登录会话共享的 HID 光标和一个键盘焦点**。因此合成的*坐标*输入（CGEvent）总是可见的：它移动真实光标并输入到聚焦的应用。

**后台 / 不在视野内的控制必须避开 CGEvent**，改走：

1. **辅助功能（AX）动作** - 按引用作用于特定元素。
2. **Apple Events / 脚本化** - 驱动可脚本化应用且无 UI。
3. **按窗口捕获** - "看到"一个窗口而不把它提到前台。

真正同时"你干活 + 我独立干活"需要一个**独立显示器或登录会话**（见 Tier 4）。

## Tier 0 - 已完成（v1，PR #345）

- `screenshot`（主显示器，感知点/像素缩放）
- `move` / `click` / `double_click` / `right_click` / `drag` / `scroll`
- `type` / `key`（组合键）
- `ui`（通过 osascript 读 AX 树）
- `cursor`、`check_permissions`

## Tier 1 - AX 语义动作  ← 后台控制的最高杠杆

按引用读取并作用于元素，无需移动光标，目标应用不必在最前。使用 `accessibility-sys`（`AXUIElementPerformAction`、`AXUIElementSetAttributeValue`、`AXUIElementCopyElementAtPosition`、`AXUIElementCopyAttributeValue`）。

- `find_element { role?, title?, value?, pid?, app? }` -> 稳定的元素句柄
- `element_at { x, y }` -> 点下的元素（AXUIElementCopyElementAtPosition）
- `press { element }` -> `AXPress`（点击后台窗口中的按钮）
- `set_value { element, value }` -> 无需焦点即可输入字段
- `get_value { element }`
- `perform_action { element, ax_action }` -> 任何已声明的 AX 动作
- `select_menu { app, path: ["File","Export…"] }` -> 驱动任何应用菜单栏

句柄格式：`pid` + AX 路径（索引链）或会话作用域的元素 id 缓存，这样模型可以按结构行动而不是按像素。

为什么重要：这就是真正的"点击你没在看的东西"能力。

## Tier 2 - 应用 / 窗口 / 系统管理

主要是 `objc2-app-kit`（`NSWorkspace`、`NSRunningApplication`）+ AX 窗口属性 + CoreGraphics 窗口列表。

- `list_apps` / `activate_app { app }` / `hide_app` / `quit_app`
- `list_windows { pid? }`（CGWindowList），带 id、标题、边界、屏上/屏外
- `focus_window` / `move_window` / `resize_window` / `minimize_window` / `close_window`
  （AX 窗口动作 - 可以瞄准后台窗口）
- `window_screenshot { window_id }` -> 即使被遮挡也能捕获特定窗口
  （现在用 `CGWindowListCreateImage`，以后用 ScreenCaptureKit）
- `spaces` 感知（应用在哪个 Space；激活可能切换 Space - 可见）

## Tier 3 - 剪贴板、输入保真度、观察

- `get_clipboard` / `set_clipboard { text }`（通过 objc2-app-kit 的 `NSPasteboard`）
- `key_down` / `key_up`（按住修饰键，游戏式输入）
- `type_into { element, text }`（AX 设置值 + 确认）比盲目打字更可靠
- `wait_for { element|condition, timeout }` 使用 `AXObserver*` 通知
  （例如等待 sheet 出现）而不是睡眠轮询
- `paste_type { text }` - 设置剪贴板 + Cmd-V 快速/大量文本输入

## Tier 4 - 真正的后台 / 并行操作（高级）

这些提供真正屏外、不干扰的控制。设置成本更高。

- **Apple Events 脚本桥**：`run_applescript { script }` / `run_jxa`。
  对可脚本化应用完全无头（Mail、Notes、Safari、Finder、Music、系统设置窗格、Terminal、许多专业应用）。无光标、无焦点。按应用的自动化权限（首次使用提示）。
- **虚拟 / 无头显示器**：把智能体的光标+窗口路由到用户没看的第二个（虚拟）显示器。选项：虚拟显示器驱动（例如 BetterDisplay/`CGVirtualDisplay` 私有 API）或真实未用显示器。让智能体把窗口移到那里并使用坐标输入，不碰用户屏幕。
- **独立登录 / 屏幕共享会话**：第二个 macOS 会话有自己的光标和焦点；智能体驱动那个。隔离最强，设置最多。
- **快捷指令集成**：调用用户的 `Shortcuts` 自动化（`shortcuts run …`）作为高层、被认可的动作。

## Tier 5 - 传感器 / 附加（可选，opt-in）

- `ocr { region|window }` 通过 Vision 框架（读取图像 / 非 AX 应用中的文本）。
- `screen_record { seconds }` 通过 ScreenCaptureKit 短片段。
- 音频输入/输出控制、通知、通过脚本切换 `do_not_disturb`。
- 摄像头/麦克风是独立的 TCC 权限；严格保持 opt-in。

## 权限（TCC）- 门禁现实

| 权限 | 解锁 | 可自动授予？ |
|---|---|---|
| **辅助功能** | CGEvent 输入、所有 AX 读写、窗口控制 | 否 - 用户切换一次（我们可以提示 + 深链） |
| **屏幕录制** | 截图、窗口/ocr 捕获 | 存在请求 API（`CGRequestScreenCaptureAccess`） |
| **自动化（Apple Events）** | 脚本化每个应用 | 首次发送时按目标应用提示 |
| **输入监控** | 读取全局输入流（只有在我们添加捕获时） | 存在请求 API |

计划：一个 `request_permissions` 动作，调用
`AXIsProcessTrustedWithOptions(prompt=true)`（把 jcode 加入列表 + 显示对话框）并深链到精确的系统设置窗格，然后轮询
`AXIsProcessTrusted()`。一次提示 + 一次开关；对辅助功能永不完全零接触
（Apple 的反恶意软件边界）。

重要：权限附加在运行 jcode 的**宿主二进制/终端**上。为了稳定体验，我们很可能需要一个带固定 bundle id 的已签名 jcode.app，这样授予的权限跨更新持久（否则每个新二进制路径都会重新提示）。

## 安全模型（高风险半径）

- 像 `bash` 一样门控：缺少必需权限时早期拒绝。
- 变更动作上的 `dry_run`：解析 + 报告目标而不行动。
- 优先 AX 语义动作而非盲目坐标点击（可审计、健壮）。
- 破坏性坐标点击上的截图/元素回显。
- 除非显式启用，否则不**捕获**全局输入（默认避开输入监控）。
- 按动作审计日志；可选的目标应用允许/拒绝列表。

## 建议的构建顺序

1. **Tier 1（AX 动作）** - 最大的能力跃升，启用后台控制。
2. **Tier 2 窗口管理 + 按窗口截图** - "看到并作用于隐藏窗口"。
3. **Tier 3 剪贴板 + AXObserver 等待** - 可靠性。
4. **`run_applescript`/JXA 桥（Tier 4）** - 许多应用的无头脚本化。
5. **虚拟显示器 / 第二会话（Tier 4）** - 真正并行、不干扰。
6. 已签名的 jcode.app bundle 实现持久权限。
7. 按需 Vision OCR（Tier 5）。

## Crates

- `accessibility-sys` 0.2（AX 读/写/观察）- crates.io 上
- `screencapturekit` 7（现代捕获）- crates.io 上；`core-graphics` 窗口列表作为回退

## 工具接口设计（已定）

### 单个工具，渐进披露

一个 `computer` 工具，`action` 分发（像 `browser`）。为了无论有多少个 tier 都保持常开上下文扁平，schema 使用**渐进披露**：

- **常开核心（约 370 token，用 tiktoken cl100k_base 测量）：**
  `screenshot, ui, ocr, click, type, key, press, set_value, run_applescript,
  setup, discover`。
- **`discover { category }`** 按需返回高级动作的完整规格
  （`mouse|keyboard|ax|windows|apps|clipboard|scripting|displays|system|all`），
  每类约 130 token，仅在用时付费。
- **共享句柄类型**（`element`、`window_id`、`region`）定义一次并复用，这样参数不会随动作倍增。

测量的常开成本：

| 设计 | 可见动作 | 常开 token |
|---|---|---|
| 当前 v1 工具 | 12 | ~720 |
| 扁平、全部 tier（约 46 个动作） | 46 | ~1,020 |
| **渐进核心** | 11 | **~370** |

后台控制是*机制*的属性，不是 tier 的属性：CGEvent = 可见；**AX 动作（press/set_value/select_menu）+ Apple Events = 后台**。

### `setup` / `check_permissions` 动作

一个一等公民的 `setup` 动作：

1. **报告**每个需求的状况：辅助功能（`AXIsProcessTrusted`）、
   屏幕录制（`CGPreflightScreenCaptureAccess`）、自动化（按应用，通过
   第一个 Apple Event），以及安装/bundle 健康。
2. **请求**它能编程式请求的：
   - `AXIsProcessTrustedWithOptions(prompt=true)` — 显示辅助功能对话框
     并预先把 jcode 加入列表（关闭状态）。
   - `CGRequestScreenCaptureAccess()` — 提示屏幕录制。
   - 对目标应用的第一个 Apple Event — 触发其自动化提示。
3. **深链**到仍然缺少的项目的精确系统设置窗格：
   - `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`
   - `…?Privacy_ScreenCapture`
   - `…?Privacy_Automation`
4. **轮询** `AXIsProcessTrusted()` 直到授予，然后报告"就绪"。

**硬限制：**辅助功能的*开关本身不能被任何 API 翻转*
（Apple 反恶意软件边界）。`tccutil` 只能重置，不能授予。因此最佳可达 UX 是
**"一两次提示 + 一次开关"**，永不零接触。

### 持久权限：已签名的应用 bundle

TCC 权限附加在**正在运行的二进制的身份**上。裸的 dev/cli 二进制
跨更新改变路径/签名，因此 macOS 每次都重新提示。要让授予持久：

- 把 jcode 作为带**稳定 bundle id**（例如 `com.jcode.app`）和 Designated Requirement 的**已签名 `.app` bundle** 发布/安装，这样辅助功能 /
  屏幕录制授予跨更新持久。
- `setup` 应检测"从不稳定/未签名路径运行"并提供安装
  正确 bundle，这样用户只授予**一次**。

### 构建顺序（更新）

1. v1 工具的渐进披露重构（核心 + `discover`）。
2. `setup` 动作（检查 + 请求 + 深链 + 轮询）。
3. Tier 1 AX 动作（后台控制）。
4. Tier 2 窗口/应用管理 + 按窗口截图。
5. Tier 3 剪贴板 + AXObserver 等待。
6. `run_applescript`/JXA 桥（Tier 4 无头脚本化）。
7. 已签名应用 bundle 实现持久权限。
8. Tier 5 OCR（Vision）。（摄像头/音频有意排除。）
9. 虚拟显示器 / 第二会话实现真正并行工作（高级）。
