# 扩展钩子

jcode 在两个层面开放外部命令：**生命周期钩子**告诉你会话内部发生了什么（观察或门控），
**派生钩子**决定有头会话出现在哪里、以何种方式出现。

合并自原「生命周期钩子」与「派生钩子」两篇。

## 一、生命周期钩子

让其他程序无需 fork jcode 就能观察或门控智能体行为。

### 配置

```toml
# ~/.jcode/config.toml
[hooks]
turn_end      = "~/bin/jcode-turn-notify"     # 观察者
session_start = ""                            # 观察者
session_end   = ""                            # 观察者
pre_tool      = "~/bin/jcode-tool-policy"     # 门控
post_tool     = ""                            # 观察者
pre_tool_timeout_ms = 5000
```

环境变量覆盖（总是优先；空值禁用配置钩子）：
`JCODE_HOOK_TURN_END`、`JCODE_HOOK_SESSION_START`、`JCODE_HOOK_SESSION_END`、
`JCODE_HOOK_PRE_TOOL`、`JCODE_HOOK_POST_TOOL`、`JCODE_HOOK_PRE_TOOL_TIMEOUT_MS`。

### 通用契约

- 钩子命令行按 shell 风格解析（引号与反斜杠转义可用）但**直接执行，不经过 shell**；
  程序路径开头的 `~/` 会展开。
- 在已知时于会话工作目录运行。
- 每个钩子都收到：

| 变量 | 含义 |
|---|---|
| `JCODE_HOOK_EVENT` | `turn_end` / `session_start` / `session_end` / `pre_tool` / `post_tool` |
| `JCODE_HOOK_SESSION_ID` | 事件所属会话 |
| `JCODE_HOOK_CWD` | 会话工作目录 |
| `JCODE_HOOK_PAYLOAD` | 镜像所有字段的 JSON（上限 16 KB） |
| `JCODE_HOOKS_DISABLED` | 总是 `1`，在嵌套 jcode 调用中抑制钩子（递归守卫） |

### 观察者钩子

`turn_end`、`session_start`、`session_end`、`post_tool` 都是**观察者**：
分离派生、即发即忘，永不阻塞或拖慢智能体，失败只记日志。

- **`turn_end`**：智能体回合完成时触发（流式回合路径，覆盖 TUI、集群 worker、无头会话）。
  额外字段：`JCODE_HOOK_STATUS`（`ok`/`error`）、`JCODE_HOOK_DURATION_MS`、`JCODE_HOOK_MODEL`、
  `JCODE_HOOK_LAST_ASSISTANT_TEXT`（前 4000 字符）、`JCODE_HOOK_ERROR`。
- **`session_start` / `session_end`**：`session_start` 在会话变为活动时触发，
  `JCODE_HOOK_SOURCE` = `create` / `attach` / `resume`；`session_end` 在正常关闭时触发（`source=close`）。
- **`post_tool`**：每次工具调用后触发。额外字段：`JCODE_HOOK_TOOL_NAME`、`JCODE_HOOK_STATUS`、
  `JCODE_HOOK_DURATION_MS`、`JCODE_HOOK_OUTPUT_BYTES`（成功）、`JCODE_HOOK_ERROR`（失败）。

### 门控钩子：`pre_tool`

在**每次工具调用前同步运行**，可以阻止调用：

- 收到 `JCODE_HOOK_TOOL_NAME`，完整工具输入 JSON 通过 **stdin** 传入
  （另有截断到 16 KB 的 `JCODE_HOOK_TOOL_INPUT`）。
- **退出 0** → 允许；**退出 2** → 阻止，钩子的 stderr（修剪、上限 2000 字符）作为工具错误
  返回给模型，模型可据此调整。
- **其他情况一律开放失败**并记警告：其他退出码、超时（`pre_tool_timeout_ms` 默认 5 秒）、
  二进制缺失、派生错误。

开放失败是刻意的：坏掉的策略脚本应降级为"无策略"，而不是弄瘫每个会话。
需要失败关闭语义时，让钩子自身健壮（它是你的信任边界，不是 jcode 的）。

### 示例：策略脚本

```bash
#!/usr/bin/env bash
# ~/bin/jcode-tool-policy
input=$(cat)
case "$JCODE_HOOK_TOOL_NAME" in
  bash)
    if grep -qE 'rm -rf /([^a-zA-Z]|$)|mkfs|dd if=' <<<"$input"; then
      echo "blocked: destructive shell command" >&2; exit 2
    fi ;;
  write|edit)
    if grep -q '"file_path":"/etc/' <<<"$input"; then
      echo "blocked: writes to /etc are not allowed" >&2; exit 2
    fi ;;
esac
exit 0
```

### 示例：回合结束通知 + 事件日志

```bash
#!/usr/bin/env bash
# ~/bin/jcode-turn-notify
if [ "$JCODE_HOOK_STATUS" = ok ]; then icon=✅; else icon=❌; fi
tmux display-message "jcode $icon ${JCODE_HOOK_SESSION_ID:0:12}" 2>/dev/null
notify-send "jcode turn $JCODE_HOOK_STATUS" "${JCODE_HOOK_LAST_ASSISTANT_TEXT:0:120}" 2>/dev/null
```

```bash
#!/usr/bin/env bash
# ~/bin/jcode-event-log —— 多个钩子指向同一脚本，按 JCODE_HOOK_EVENT 分发
echo "$JCODE_HOOK_PAYLOAD" >> ~/.local/state/jcode-events.jsonl
```

### 设计说明

- 钩子查找由配置驱动，配置重载时重新读取，**无需重启**即可增改。
- 热路径（`pre_tool`/`post_tool`）在构建载荷前先检查是否配置了钩子，未配置时几乎零成本。
- 递归守卫（`JCODE_HOOKS_DISABLED=1`）让钩子可安全调用 `jcode` CLI 而不在嵌套进程中重触发。

## 二、派生钩子（spawn hook）

jcode 会在多种流程中打开新的终端窗口：集群智能体派生（`spawn_mode=visible`）、
新终端恢复、自研会话、重启恢复、中继启动。默认它检测已安装的终端模拟器
（kitty、wezterm、alacritty、gnome-terminal 等）并开一个新窗口。

**派生钩子让外部程序接管这次派生**，由它决定会话出现在哪里、以何种方式：
tmux 窗格、kitty 标签页、zellij 窗格、herd 类包装应用的标签页、特定显示器/工作区等。

### 配置

```toml
[terminal]
spawn_hook = "tmux new-window"
```

```bash
export JCODE_SPAWN_HOOK="tmux new-window"
export JCODE_SPAWN_HOOK=     # 空值禁用配置文件中的钩子
```

环境变量总是优先。

### 契约

```
<spawn_hook> <jcode-binary> <args...>
```

- 钩子命令按 shell 风格解析，但直接执行、不经过 shell。
- jcode 二进制与完整参数作为额外 argv 追加（熟悉的 `$TERMINAL -e <cmd>` 约定）。
- 工作目录是会话工作目录；钩子进程被分离，jcode 不等待。
- 钩子**启动**失败（二进制缺失、解析错误）时记警告并回退到内置终端检测；
  但钩子启动成功却内部失败地退出**不会**触发回退，路由脚本需自己处理回退。

### 元数据环境变量

| 变量 | 含义 |
|---|---|
| `JCODE_SPAWN_KIND` | 派生原因：`swarm-agent` / `resume` / `selfdev` / `restart` / `jade-relay` |
| `JCODE_SPAWN_SESSION_ID` | 窗口将运行的会话 |
| `JCODE_SPAWN_TITLE` | 建议的窗口/标签页标题（含会话图标 + 名称） |
| `JCODE_SPAWN_CWD` | 会话工作目录 |
| `JCODE_SPAWN_PROGRAM` | 要执行的 jcode 二进制路径 |
| `JCODE_SPAWN_COMMAND` | 完整命令行（shell 转义），供接受单个 shell 字符串的钩子 |
| `JCODE_SPAWN_SWARM_ID` | （集群派生）智能体加入的集群 |
| `JCODE_SPAWN_COORDINATOR_SESSION_ID` | （集群派生）请求该派生的协调者会话 |
| `JCODE_FRESH_SPAWN` | 新窗口交接时为 `1` |

### 客户端终端环境（多终端路由）

服务器是长驻进程，启动时只捕获一次终端标识 env（`ZELLIJ_SESSION_NAME`、`TMUX`、`DISPLAY`、
`KITTY_WINDOW_ID` 等）。此后在新终端里连接客户端时，服务器的副本已过期，
服务器执行的派生钩子会错误指向*旧*终端。

解决方式：每个连接客户端把自己的终端标识 env 快照发给服务器，派生钩子运行时服务器
重新导出**请求客户端**的值：

- 原生变量（如 `ZELLIJ_SESSION_NAME`）被覆盖为客户端的值；
- 同时导出 `JCODE_CLIENT_<NAME>` 别名（`JCODE_CLIENT_ZELLIJ_SESSION_NAME`、
  `JCODE_CLIENT_TMUX`、`JCODE_CLIENT_DISPLAY` 等），供钩子显式区分客户端与服务器的终端。

覆盖键包括终端复用器（zellij / tmux / screen）、终端模拟器（kitty / wezterm / ghostty /
alacritty / iTerm / Windows Terminal / handterm）与显示服务器（`DISPLAY`、`WAYLAND_DISPLAY`）；
只转发客户端实际设置的变量。

### 内置行为与示例

当请求客户端在 tmux 内时，内置启动器会自动在针对该 `TMUX_PANE` 的右侧窗格打开有头派生
（覆盖 `/split`、`/fork`、新终端恢复、自研、可见智能体派生）。`JCODE_TERMINAL` 可显式选择终端模拟器，
配置的 `spawn_hook` 优先级最高。

```toml
# tmux：每个智能体一个窗口
[terminal]
spawn_hook = "tmux new-window"
# 或显式保留右侧窗格
# spawn_hook = "tmux split-window -h"

# kitty：每个智能体一个标签页（远程控制）
[terminal]
spawn_hook = "kitty @ --to unix:/tmp/kitty.sock launch --type=tab --"
```

自定义路由脚本（完全控制位置、标题、集群与恢复路由）：

```bash
#!/usr/bin/env bash
# ~/bin/jcode-spawn-router；argv = 要运行的 jcode 命令
case "$JCODE_SPAWN_KIND" in
  swarm-agent)
    tmux new-window -n "swarm:${JCODE_SPAWN_SWARM_ID:0:8}" "$@" 2>/dev/null || tmux split-window "$@" ;;
  *)
    kitty --title "$JCODE_SPAWN_TITLE" -e "$@" & ;;
esac
```

接受单个 shell 字符串的启动器用 `$JCODE_SPAWN_COMMAND`：

```bash
#!/usr/bin/env bash
zellij action new-pane -- bash -lc "$JCODE_SPAWN_COMMAND"
```

**编程式发现**：包装 jcode 的程序可在自己启动的服务器进程环境中设置 `JCODE_SPAWN_HOOK`，
此后该服务器执行的每一次有头派生（含协调者经套接字请求的集群智能体）都会走包装器的钩子。

### 聚焦钩子

要把已有会话窗口带到前台时（如启动自研窗口后），jcode 默认在 X11 上尽力做 wmctrl/xdotool
标题搜索——这在 Wayland 或复用器内不可用，而拥有布局的包装器本应拥有聚焦：

```toml
[terminal]
spawn_hook = "tmux new-window"
focus_hook = "~/bin/jcode-focus"   # env: JCODE_FOCUS_SESSION_ID, JCODE_FOCUS_TITLE
```

环境变量覆盖 `JCODE_FOCUS_HOOK`（空值禁用配置文件钩子）；钩子启动失败时回退内置聚焦路径。
