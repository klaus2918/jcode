# jcode 包装 / 脚本指南

本文档描述面向包装器、脚本和其他调用 `jcode` 的程序的非交互式 CLI 界面。

## 推荐标志

包装器默认使用这些标志：

```bash
jcode --quiet --no-update --no-selfdev ...
```

- `--quiet` 抑制非错误的 CLI/状态输出
- `--no-update` 避免更新检查的噪音/工作
- `--no-selfdev` 避免仓库自动检测改变运行时行为

## 发现可用模型

列出可以传给 `-m/--model` 的模型名：

```bash
jcode --quiet model list
jcode --quiet model list --json
jcode --quiet --provider openai model list --json
```

## 发现提供商与当前选择

列出可以传给 `-p/--provider` 的提供商 ID：

```bash
jcode --quiet provider list
jcode --quiet provider list --json
```

检查当前请求和解析出的提供商/模型选择：

```bash
jcode --quiet provider current
jcode --quiet --provider openai --model gpt-5.4 provider current --json
```

详细的人类可读摘要：

```bash
jcode --quiet model list --verbose
```

## 运行单次提示词并返回 JSON

```bash
jcode --quiet run --json "Reply with exactly OK"
```

## 以 NDJSON 流式输出单次提示词

```bash
jcode --quiet run --ndjson "Reply with exactly OK"
```

典型事件类型：

- `start`
- `connection_phase`
- `connection_type`
- `text_delta`
- `text_replace`
- `tool_start`
- `tool_input`
- `tool_exec`
- `tool_done`
- `tokens`
- `done`
- `error`

最终的 `done` 事件包含拼装好的文本和用量摘要。

示例结构：

```json
{
  "session_id": "session_...",
  "provider": "OpenAI",
  "model": "gpt-5.4",
  "text": "OK",
  "usage": {
    "input_tokens": 123,
    "output_tokens": 7,
    "cache_read_input_tokens": 0,
    "cache_creation_input_tokens": null
  }
}
```

## 检查认证状态

```bash
jcode --quiet auth status
jcode --quiet auth status --json
```

JSON 输出包含：

- `any_available`
- `providers[]`
  - `id`
  - `display_name`
  - `status`
  - `method`
  - `auth_kind`
  - `recommended`

## 检查构建/版本信息

```bash
jcode --quiet version
jcode --quiet version --json
```

JSON 输出包含：

- `version`
- `git_hash`
- `git_tag`
- `build_time`
- `git_date`
- `release_build`

## 注意事项

- JSON 命令的设计是让预期的机器可读结果打印到 `stdout`
- 使用 `--quiet` 时，面向包装器的命令应保持 `stderr` 为空，除非有真实的警告/错误
- `jcode model list` 和 `jcode run --json` 不需要 TUI
- `jcode model list` 不需要已在运行的共享服务器
