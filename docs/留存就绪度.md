# 留存就绪度

jcode 区分两个不应共享标签的问题：

1. **留存就绪度**：确定性的产品属性，让回访变得有用且便宜。
2. **观测到的留存**：真实的、隐私安全的队列是否真的回访并完成有意义的工作。

前者是回归测试。后者是产品结果。确定性测试绝不能冒充 D1、D7 或 D30 的用户留存。

## 确定性合成队列

运行：

```bash
cargo test -p jcode-app-core --lib retention_readiness -- --nocapture
```

评估器驱动真实的 `Agent`、提供商接口、持久化的 `Session` 和磁盘恢复路径，穿过标记的阶段边界：

| 边界 | 旅程 |
|---|---|
| D0 | 发送一个激活提示词，要求有用的首个价值加上持久的会话。 |
| D1 | 从持久化会话创建新的 Agent 和提供商注册表。不重述上下文继续。验证记录、标题、工作目录和记忆标记。 |
| D7 | 创建另一个 Agent 和提供商注册表，然后注入一次提供商中断。要求失败的 D7 提示词本身持久化，然后一次重试恢复。最终结果只有在 D0 和 D1 上下文都存在时才返回。 |

D0/D1/D7 是确定性阶段标签，不是墙钟睡眠。

### 维度

| 维度 | 权重 | 原始证据 |
|---|---:|---|
| 激活 / 首个价值 | 25% | 有用的 D0 响应和持久化会话 |
| 回访摩擦 | 20% | 上下文重述步骤和提示词到价值 |
| 连续性 | 20% | 先前的记录、标题、工作区和记忆标记在磁盘再水化后存活 |
| 持久性 | 15% | 会话保持可加载，历史在注入的故障中存活 |
| 故障恢复 | 10% | 中断浮现并在一次重试中回到有用价值 |
| 复合价值 | 10% | D7 成功需要两个先前边界的上下文 |

行为得分是加权几何平均：

```text
behavioral = 100 * product((dimension_score / 100) ^ weight)
```

因此零分维度会让行为得分崩溃，而不是被无关的满分维度掩盖。关键行为还有直接断言。

## 证据覆盖

评分器维护一个显式因子注册表：

- **已评分（6）**：响应首个价值、回访摩擦、连续性、重启/故障持久性、恢复、复合上下文。
- **延后（2）**：工具/文件编辑支撑的首个价值，以及按提供商-操作系统矩阵的持久化凭据/提供商重建。
- **仅观测（1）**：真实 D1/D7/D30 有意义工作的留存。这不计入确定性分母。

当前确定性结果：

```text
Behavioral readiness: 100 / 100
Evidence coverage:      75 / 100 (6/8 deterministic factors)
Coverage-adjusted:      75 / 100
```

诚实的头条是 **75/100 覆盖调整后的留存就绪度**，而不是"100% 留存"。

夹具在每个阶段重建提供商注册表，但它刻意不把夹具提供商当作生产凭据能在重启后存活的证明。认证连续性仍是延后的提供商-操作系统矩阵的一部分。

安装、PATH、升级和卸载持久性由 `scripts/setup_friction_eval.sh` 单独演练。它们应保持独立的记分卡，这样宽泛的安装套件无法淹没对话连续性失败。（注：该脚本已随 feature-simplification 精简移除，2026-08-16；安装回归由 `scripts/test_install_conversion.sh` 及 CI 的 powershell-syntax/installer 门继续覆盖。）

## 观测对应物

真实留存应使用由有意义工作激活的队列，而不是原始启动：

```text
D7 meaningful-work retention =
  activated users with >=1 successful assistant/tool outcome in the D7 window
  -----------------------------------------------------------------------------
  users whose first successful assistant/tool outcome occurred on D0
```

至少报告：

- 首次成功助手响应后的 D1、D7 和 D30 回访
- 首次成功工具或文件编辑后的 D1、D7 和 D30 回访
- 每个活跃用户的重复成功工作流
- 升级后的回访
- 认证恢复成功后有意义的后续工作

jcode 已记录粗略的活跃日辅助（`active_days_7d` 和 `active_days_30d`）。这些是有用的参与信号，但它们本身不是队列留存，因为它们没有把分母锚定到激活事件，也不要求有意义且成功的产出。

## 校准循环

1. 发现确定性因子的回归或弱点。
2. 改进该因子并保持记分卡绿色。
3. 发布该变更。
4. 对比相应的隐私安全真实队列。
5. 只有在多次发布显示稳定关系时才调整因子权重。绝不为复现某个期望留存数字而调谐确定性测试。
