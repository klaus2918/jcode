# 认证凭据来源（单一事实来源）

本文档存在是因为同一个困惑反复出现：智能体（或人）grep `ANTHROPIC_API_KEY` / `sk-ant-api`，找不到，读到过时的 `auth-validation.json` 条目说"已过期"，然后错误地得出"没有可用凭据"的结论。实际上凭据存在且有效；它只是住在天真搜索没找的地方。

如果你在调试"提供商 X 有凭据吗？"，先读这个。

## 两个"双认证"提供商：Anthropic 和 OpenAI

Anthropic/Claude 和 OpenAI 各支持**两条完全独立的凭据路径**，作为**两个独立的登录提供商**呈现：

| 概念 | 登录提供商 id | 认证类型 | 凭据所在地 |
|--------------------|-------------------|-----------|-------------------------------------------------------------|
| Claude，OAuth/订阅 | `claude` | OAuth | `~/.jcode/auth.json` → `anthropic_accounts[].access`（`sk-ant-oat...`） |
| Claude，API 密钥 | `anthropic-api` | API 密钥 | `ANTHROPIC_API_KEY` env **或** `~/.config/jcode/anthropic.env` |
| OpenAI，OAuth | `openai` | OAuth | `~/.jcode/openai-auth.json`（Codex/ChatGPT 登录） |
| OpenAI，API 密钥 | `openai-api` | API 密钥 | `OPENAI_API_KEY` env **或** `~/.config/jcode/openai.env` |

让人困惑的关键事实：

- **OAuth 令牌不是 API 密钥。** Anthropic OAuth 令牌是 `sk-ant-oat01-...`（刷新令牌 `sk-ant-ort01-...`）。直接 API 密钥是 `sk-ant-api03-...`。grep `sk-ant-api` 会漏掉纯 OAuth 设置，反之亦然。
- **API 密钥通常在应用配置目录里，不是环境变量。** 规范存储是 `~/.config/jcode/anthropic.env`（XDG `$XDG_CONFIG_HOME/jcode/anthropic.env`），由 `jcode login --provider anthropic-api` 写入。`printenv ANTHROPIC_API_KEY` 返回空**不**意味着没有密钥。
- `~/.jcode/auth.json` 只保存**OAuth 账户**，绝不保存 API 密钥。
- `claude` 和 `anthropic-api` 是**不同提供商**，可用性不同。有 Claude 订阅登录（OAuth）**不**让 `anthropic-api` 可用，反之亦然。

### 如何真正检查（不要猜）

```sh
# 对每个提供商诚实、归一化的答案：
jcode auth status --json
```

每个提供商条目报告 `status`、`auth_kind`（"OAuth" vs "API 密钥"）、`credential_source`（环境变量 / 应用配置文件 / jcode 管理文件）和精确 `method`。这是规范面；优先于 grep 文件。

编程上，单一事实来源是 `crates/jcode-base/src/auth/mod.rs` 中的 `AuthStatus::assessment_for_provider(descriptor)`，它返回 `ProviderAuthAssessment`。

## 通过配置选择默认

`~/.jcode/config.toml`：

```toml
[provider]
default_provider = "claude"        # Claude 订阅（OAuth）
# default_provider = "anthropic-api" # 通过直接 Anthropic API 密钥的 Claude
default_model = "claude-opus-4-8"
anthropic_reasoning_effort = "xhigh"
```

- `default_provider = "claude"` 使用 OAuth/订阅凭据。
- `default_provider = "anthropic-api"` 使用直接 API 密钥。在此模式下运行时**不**回退到 OAuth：如果没配置 API 密钥，请求失败。确保 `~/.config/jcode/anthropic.env`（或 `ANTHROPIC_API_KEY`）存在。

完整的别名/词汇映射（运行时 env、路由稳定 id、CLI `--provider`、模型前缀）集中在 `crates/jcode-provider-core/src/auth_mode.rs`（`AuthRoute`）。不要手工重新解析这些字符串；走 `AuthRoute`。

## 为什么"已过期"有误导性：验证缓存不是实时状态

`~/.jcode/auth-validation.json` 缓存每个提供商**最近一次**运行时认证测试的结果。它是历史记录，不是当前凭据状态。此后已自动刷新的 OAuth 令牌仍可能在这里显示几天前的"验证失败 / 已过期"条目。

为避免把过时记录当作当前事实，`format_record_label`（`crates/jcode-base/src/auth/validation.rs`）把任何早于 `doctor::VALIDATION_STALE_AFTER_MS`（7 天）的记录标记为 `stale, ... re-validate`。把过时记录当作"未知，重新检查"，绝不当作事实。用以下命令重新验证：

```sh
jcode auth-test --provider <id>
```

## "提供商 X 已认证吗？"的快速决策树

1. 运行 `jcode auth status --json` 读取**特定**登录提供商 id 的条目（`claude` vs `anthropic-api` 是不同的！）。
2. 如果必须检查文件：OAuth → `~/.jcode/auth.json`（和外部导入）；API 密钥 → `ANTHROPIC_API_KEY` env 或 `~/.config/jcode/<provider>.env`。
3. 忽略超过 7 天的 `auth-validation.json` 裁决（显示为 `stale`）；改为重新运行 `jcode auth-test`。

## 从其他智能体工具导入凭据

全新安装时 jcode 可以**复用其他编码智能体留下的登录**，包括 OAuth 令牌和 API 密钥。检测是同意门控的：jcode 列出找到的来源，只有在你逐个批准后才读取它们（`crates/jcode-base/src/auth/external.rs`、`unconsented_sources` / `trust_external_auth_source`）。不会有任何东西复制进 jcode 自己的存储；外部文件就地读取。

共享的 `auth.json` 风格来源（`ExternalAuthSource`）：

| 工具 | 认证文件路径 | 磁盘形态 |
|-----------|------------------------------------|------------------------------------------------------------------------------|
| OpenCode | `~/.local/share/opencode/auth.json` | 扁平 `{ provider: { type: "oauth", access, refresh, expires } \| { type: "api", key } }` |
| pi | `~/.pi/agent/auth.json` | 扁平 `{ provider: { type: "oauth", ... } \| { type: "api_key", key } }`（key 可能是 `$ENV` 引用） |
| OpenClaw | `~/.openclaw/agent/auth.json`、`~/.openclaw/agents/<id>/agent/auth-profiles.json`、`~/.openclaw/agents/<id>/agent/auth.json`、`~/.openclaw/credentials/oauth.json` | 旧版扁平 pi 形态，或当前的 `{ "profiles": { "<provider>:<name>": ... } }` 存储（第一个存在的路径胜出；偏好 `main` 智能体和 `:default` 配置） |
| Hermes | `~/.hermes/auth.json` | 嵌套 `{ credential_pool: { provider: [ { auth_type, access_token, refresh_token, expires_at_ms } ] }, providers: {...} }` |

备注：

- pi/OpenClaw 中是 `$ENV_VAR` 引用的 API 密钥值按环境解析；以 `!`（shell 命令）开头的值**绝不执行**并被跳过。
- Hermes 在 `api_key` 凭据池条目的 `access_token` 字段存储字面 API 密钥；它的许多提供商只存 env 变量*名*，因此除非设置了该 env 变量，那些导入不了任何东西。
- Claude Code、Codex、Gemini CLI、GitHub Copilot 和 Cursor 有各自的工具特定导入器（见 `auth/claude.rs`、`auth/codex.rs`、`auth/gemini.rs`、`auth/copilot.rs`、`auth/cursor.rs`）。
