# 重构路线图

本文档定义了在保持行为不变的前提下，安全、渐进地重构 jcode 的路径。

另见：

- [`docs/代码质量10-10计划.md`](plans/代码质量10-10计划.md)：代码质量目标、分阶段提升计划以及初始热点重构清单。
- [`docs/编译性能计划.md`](plans/编译性能计划.md)：编译速度基线、战术性构建工作流以及工作区/crate 拆分路线图。

## 目标

- 重构期间保持现有会话和用户工作流稳定。
- 通过可重复的检查尽早暴露回归。
- 分阶段降低架构耦合（而不是一次性大爆炸式重写）。

## 不可妥协的安全规则

1. 重构运行使用隔离环境：

   - `scripts/refactor_shadow.sh serve`
   - `scripts/refactor_shadow.sh run`
   - `scripts/refactor_shadow.sh build --release`

2. 每次重构合并前，运行阶段 1 验证套件：

   - `scripts/refactor_phase1_verify.sh`

3. 警告数量不得高于基线：

   - `scripts/check_warning_budget.sh`

4. 合并前运行安全预检：

   - `scripts/security_preflight.sh`

5. 优先进行保持行为的移动（提取/重命名/拆分），然后再做逻辑变更。

## 阶段计划

### 阶段 1：安全与卫生（当前）

- 为重构添加隔离的开发/运行工作流。
- 添加可重复的验证脚本。
- 添加警告预算守卫，防止警告漂移。
- 在不改变功能的情况下清理低风险的警告债。

### 阶段 2：CLI 分解

- 将 `main.rs` 的子命令处理程序移到专注的 `src/cli/*` 模块中。
- 保持顶层 `main()` 只做解析 + 分发。

### 阶段 3：服务器分解

- 按职责拆分 `server.rs`（会话生命周期、调试 API、集群协调、重载/更新）。
- 在可行处用类型化枚举替换字符串化状态。

### 阶段 4：智能体回合循环统一

- 将重复的回合循环变体合并为一个共享引擎，并带可插拔的事件汇。

### 阶段 5：TUI 状态/Reducer 拆分

- 分离应用状态、命令解析、远程事件归约和渲染控制。

### 阶段 6：提供商状态隔离

- 通过将缓存移入显式状态持有者来减少全局可变状态。

## 验证矩阵

- 编译：`cargo check -q`
- 编译计时：`scripts/bench_compile.sh check --runs 3 --touch <hot-file>` 和 `scripts/bench_compile.sh release-jcode --runs 3`
- 警告：`scripts/check_warning_budget.sh`
- 安全：`scripts/security_preflight.sh`
- 单元 + 集成测试：`cargo test -q`
- 端到端测试：`cargo test --test e2e -q`
- 综合：`scripts/refactor_phase1_verify.sh`
