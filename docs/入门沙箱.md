# 入门沙箱

如果你想在不触碰真实认证状态的情况下反复迭代入门流程，请使用一个以 `JCODE_HOME` 和 `JCODE_RUNTIME_DIR` 为根目录的独立沙箱。

本仓库已支持这种隔离：

- `JCODE_HOME` 将 jcode 拥有的状态（如 `~/.jcode`）重定向到沙箱目录。
- `JCODE_HOME` 同时将应用配置重定向到 `JCODE_HOME/config/jcode`。
- `JCODE_RUNTIME_DIR` 重定向套接字和其他临时运行时文件。
- 外部认证信任决定存储在沙箱配置中，因此全新沙箱开始时没有任何受信任的外部认证导入。

## 快速开始

```bash
scripts/onboarding_sandbox.sh fresh
```

这会给你一个状态隔离的干净 jcode 启动。

## 用你的真实登录测试（在沙箱中导入它们）

干净的沙箱完全隔离，因此入门流程中的"导入现有登录"步骤没有可导入的内容。要对你的真实账户演练导入 + "从上次中断处继续"步骤，请把真实凭据和记录文件的副本植入沙箱：

```bash
# 复制真实的外部登录（Codex/Claude/Gemini/Copilot/Cursor/OpenCode/pi）
scripts/onboarding_sandbox.sh seed-real-logins

# 同时复制真实的 Codex/Claude 记录，让"继续会话"步骤有真实历史可恢复：
scripts/onboarding_sandbox.sh seed-real-logins --with-transcripts

# 或者一步到位：重置、植入并启动 jcode
scripts/onboarding_sandbox.sh fresh-real --with-transcripts
```

工作原理：设置 `JCODE_HOME` 后，jcode 将所有外部凭据和记录查找解析到 `$JCODE_HOME/external/<与-$HOME-相同的相对路径>`。`seed-real-logins` 将你的真实文件复制到那里，因此检测和导入的行为与一台已安装这些工具的全新机器完全一致。这些副本是真实令牌，因此沙箱保持仅本地运行；你原来的 `$HOME` 文件永远不会被移动、重写或删除。

植入后，直接启动沙箱并走一遍入门流程；它会检测并提供导入每个真实登录：

```bash
scripts/onboarding_sandbox.sh jcode
```

## 常用命令

```bash
# 显示确切的 env 变量和沙箱路径
scripts/onboarding_sandbox.sh env
scripts/onboarding_sandbox.sh status

# 从空白入门状态重新开始
scripts/onboarding_sandbox.sh reset
scripts/onboarding_sandbox.sh fresh

# 登录提供商而不触碰你的常规 jcode 配置
scripts/onboarding_sandbox.sh login openai
scripts/onboarding_sandbox.sh login claude
scripts/onboarding_sandbox.sh auth-status

# 将登录后的沙箱保存为可复用的本地夹具
scripts/onboarding_sandbox.sh fixture-save normal-openai

# 之后恢复该精确认证状态，无需重复浏览器登录
scripts/onboarding_sandbox.sh fixture-load normal-openai
scripts/onboarding_sandbox.sh auth-status

# 或在夹具支撑的沙箱中加载并运行一条命令
scripts/onboarding_sandbox.sh fixture-run normal-openai -- auth-test --provider openai --no-smoke

# 在沙箱中运行任意 jcode 命令
scripts/onboarding_sandbox.sh jcode auth status
scripts/onboarding_sandbox.sh jcode pair
```

## 可复用的本地认证夹具

对于重复的登录测试，使用本地认证夹具。夹具是沙箱 `JCODE_HOME` 在你把它放到某个有趣状态后的副本，例如典型的已登录 OpenAI 用户、过期令牌状态或外部认证导入审批状态。

夹具存储默认为 `.tmp/auth-fixtures`，这是有意的本地开发状态。夹具可能包含真实的 OAuth 令牌或 API 密钥引用，因此不要提交或分享它们。

推荐工作流：

```bash
# 一次性搭建真实的已登录状态
scripts/onboarding_sandbox.sh reset
scripts/onboarding_sandbox.sh login openai
scripts/onboarding_sandbox.sh auth-status
scripts/onboarding_sandbox.sh fixture-save normal-openai

# 之后快速重复循环
scripts/onboarding_sandbox.sh fixture-load normal-openai
scripts/onboarding_sandbox.sh auth-status
scripts/onboarding_sandbox.sh jcode auth-test --provider openai
```

也可以直接使用更底层的辅助脚本：

```bash
scripts/auth_fixture.sh list
scripts/auth_fixture.sh save normal-openai
scripts/auth_fixture.sh load normal-openai
scripts/auth_fixture.sh run normal-openai -- auth status
```

有用的环境变量覆盖：

- `JCODE_ONBOARDING_SANDBOX`：选择哪个沙箱接收夹具。
- `JCODE_ONBOARDING_DIR`：使用显式的沙箱目录。
- `JCODE_AUTH_FIXTURE_DIR`：使用仓库外的夹具存储，例如
  `~/.local/share/jcode-auth-fixtures`。

建议的夹具名称：

- `normal-openai`
- `normal-claude`
- `expired-openai`
- `api-key-openrouter`
- `external-opencode-approved`

## 移动端入门模拟器

仓库还有一个可重置的无头移动模拟器，带有预定义的入门场景。

```bash
# 在后台启动模拟器
scripts/onboarding_sandbox.sh mobile-start onboarding

# 检查它
scripts/onboarding_sandbox.sh mobile-status
scripts/onboarding_sandbox.sh mobile-state
scripts/onboarding_sandbox.sh mobile-log

# 重置回场景起点
scripts/onboarding_sandbox.sh mobile-reset
```

目前支持的场景：

- `onboarding`
- `pairing_ready`
- `connected_chat`

## 为什么这样更安全

全新沙箱意味着：

- 不重用真实的 jcode 配置文件
- 不重用真实的运行时套接字
- 不重用之前受信任的外部认证来源
- 一个 `reset` 就能全部清空

使用夹具时，沙箱仍与你的常规 jcode 状态隔离，但加载的夹具可能有意包含来自较早沙箱登录的认证状态副本。

## 推荐工作流

对于紧凑的入门迭代，使用这个循环：

1. `scripts/onboarding_sandbox.sh reset`
2. `scripts/onboarding_sandbox.sh fresh`
3. 走一遍入门流程
4. 调整代码
5. 重复

如果你专门迭代移动端入门 UX，保持模拟器运行，并在每次迭代之间使用 `mobile-reset`。

## 注意事项

该沙箱设计用于隔离 jcode 拥有的状态和受信任的外部导入状态。如果你之后决定测试外部工具的显式导入/重用流程，请有意识地进行，并将其视为与首次运行入门不同的独立测试用例。
