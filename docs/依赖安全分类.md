# 依赖安全分类

最后审核：2026-05-14

本文件跟踪 jcode 当前的 `cargo audit` 发现及计划修复路径。
它不是白名单。它是分类记录，让公告可见且可操作。

## 当前公告

|---|---|---|---|---|---|

## 优先级顺序

1. 通过 rustls 栈的 `rustls-webpki` TLS 公告
2. 通过 `imap-proto` 的 `lexical-core`
3. 如果 Jcode 启用 `boring-tls` 则 `lettre`
4. 通过 `ratatui` 的 `lru`
5. 通过 `syntect` 的 `bincode`
6. 通过多个传递依赖的 `paste` / `rand`

## 备注

- 以上公告都不是提供商认证重构引入的。
- 提供商/认证加固工作应独立于这些依赖升级继续进行。
- `RUSTSEC-2026-0217`（`tract-nnef` 0.21.10，NNEF 张量解析器中的整数溢出）已于 2026-07-30 通过把 `jcode-embedding` 移到 `tract` 0.23 解决。内联 `0.21.16` 修复不可达：`tract-data 0.21.16` 固定 `half =2.4.1`，而 `naga`（通过 `jcode-desktop2` 中的 `vello`）需要 `half ^2.5`。0.23 系列移除了该固定。这很重要，因为解析器处理的是运行时下载的模型而不是二进制中自带的模型，因此忽略并不明确安全。见 #657。
- `RUSTSEC-2024-0320`（`yaml-rust`）已于 2026-03-05 通过修剪 `syntect` 特性为内置语法/主题转储而非 YAML 加载，从依赖图中移除。
- `RUSTSEC-2026-0194` / `RUSTSEC-2026-0195`（`quick-xml` 0.39.2）：只能通过 `wayland-scanner` 到达，它是桌面 crate 的 winit 栈中的构建时 proc-macro。它在编译期间解析受信任的、供应商化的 Wayland 协议 XML，运行时从不触碰不可信输入。修复在上游：`wayland-scanner` 需要移到 `quick-xml >= 0.41`。已于 2026-07-04 在 `scripts/security_preflight.sh` 中分类并忽略。
- `scripts/security_preflight.sh` 忽略上面明确分类的漏洞公告（`lettre` 和 `rustls-webpki`），使 CI 保持可操作。新漏洞默认仍会使 CI 失败。
- 更改依赖版本之前，运行：
  - `cargo check`
  - `cargo test -j 1`
  - `scripts/security_preflight.sh`
