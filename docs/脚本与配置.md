# 脚本与配置

本文面向两类读者：**包装 jcode 的程序**（非交互式 CLI 界面）与
**想统一全局行为的用户**（AGENTS.md 全局宪法 + prompt overlay）。
合并自原「包装脚本指南」与「全局宪法」。

## 一、非交互式 CLI（给包装器/脚本）

### 推荐标志

```bash
jcode --quiet --no-update --no-selfdev ...
```

- `--quiet` 抑制非错误的 CLI/状态输出；
- `--no-update` 避免更新检查的噪音与开销；
- `--no-selfdev` 避免仓库自动检测改变运行时行为。

### 发现模型与 provider

```bash
jcode --quiet model list                  # 可传给 -m/--model 的模型名
jcode --quiet model list --json
jcode --quiet model list --verbose        # 人类可读摘要（含 provider/选择）
jcode --quiet --provider openai model list --json

jcode --quiet provider list               # 可传给 -p/--provider 的 provider id
jcode --quiet provider list --json

jcode --quiet provider current            # 当前请求与最终解析出的选择
jcode --quiet --provider openai --model gpt-5.4 provider current --json
```

### 单次提示词

```bash
jcode --quiet run --json   "Reply with exactly OK"    # 一次性 JSON 结果
jcode --quiet run --ndjson "Reply with exactly OK"    # 流式 NDJSON 事件
```

NDJSON 事件类型：`start`、`connection_phase`、`connection_type`、`text_delta`、`text_replace`、
`tool_start`、`tool_input`、`tool_exec`、`tool_done`、`tokens`、`done`、`error`。
最后的 `done` 含拼装好的文本与用量摘要：

```json
{
  "session_id": "session_...",
  "provider": "OpenAI",
  "model": "gpt-5.4",
  "text": "OK",
  "usage": {
    "input_tokens": 123,
    "output_tokens": 7,
    "cache_read_input_tokens": 0,
    "cache_creation_input_tokens": null
  }
}
```

### 状态与版本

```bash
jcode --quiet auth status [--json]     # any_available；providers[]{id,display_name,status,method,auth_kind,recommended}
jcode --quiet version [--json]         # version, git_hash, git_tag, build_time, git_date, release_build
```

### 注意事项

- JSON 命令把机器可读结果打到 `stdout`；配合 `--quiet` 时 `stderr` 应保持为空，
  除非确有警告或错误。
- `jcode model list` 与 `jcode run --json` **不需要 TUI**；
- `jcode model list` 也**不需要**已在运行的共享服务器。

## 二、全局宪法（AGENTS.md）

### 设计

jcode 在会话启动时构建系统提示词，自动读取并拼接若干指令文件：

- **项目级**：`<工作目录>/AGENTS.md`（标签 `Project Instructions (AGENTS.md)`）
- **全局级**：全局 AGENTS.md（标签 `Global Instructions (~/AGENTS.md)`）

全局级作用于所有项目、所有会话，即"统一全局约束"的落点。

### 全局 AGENTS.md 的读取位置（二选一，互斥）

读取逻辑在 `crates/jcode-base/src/prompt.rs` 的 `load_agents_md_files_from_dir`，
经 `user_home_path("AGENTS.md")` 解析：

```
设置了 JCODE_HOME  →  $JCODE_HOME/external/AGENTS.md
未设置 JCODE_HOME  →  <系统主目录>/AGENTS.md
```

其中 `JCODE_HOME` 是 jcode 的根数据目录（`crates/jcode-storage/src/lib.rs` 的 `jcode_dir()`）：

```
设置了 JCODE_HOME  →  $JCODE_HOME
未设置 JCODE_HOME  →  <主目录>/.jcode
```

**关键点**：两条路径互斥而非叠加。设置了 `JCODE_HOME` 后，宪法必须放在
`$JCODE_HOME/external/AGENTS.md`，否则不生效。

| 平台（未设 JCODE_HOME） | 全局 AGENTS.md |
|---|---|
| Windows | `C:\Users\<用户名>\AGENTS.md` |
| Linux / macOS | `~/AGENTS.md` |

### 配置方案

**方案 1：使用 JCODE_HOME（推荐，根目录集中管理）**

```powershell
[Environment]::SetEnvironmentVariable('JCODE_HOME', "C:\Users\<用户名>\.jcode", 'User')
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.jcode\external"
Copy-Item -Force .\AGENTS.md "$env:USERPROFILE\.jcode\external\AGENTS.md"
```

若 `C:\Users\<用户名>\.jcode` 已有 jcode 数据（skills、配置等），`JCODE_HOME` 必须指向该目录本身，
否则现有数据不会被读取。

**方案 2：不设置 JCODE_HOME（最简单）**

```powershell
Copy-Item -Force .\AGENTS.md "$env:USERPROFILE\AGENTS.md"
```

### 生效时机与验证

- AGENTS.md **在会话启动时读取**：改完要新开会话/重启 jcode，运行中的会话不会重新加载。
- 验证：新会话执行 `/info`，提示词统计中应显示 `global ~/AGENTS.md: <字符数>` 已加载。

### 更底层的叠加层

除 AGENTS.md 外还有 Prompt Overlay，直接叠加进系统提示词：

| 层 | 文件 | 作用域 |
|---|---|---|
| 项目规则 | `<工作目录>/AGENTS.md` | 仅当前项目 |
| **全局宪法** | `$JCODE_HOME/external/AGENTS.md`（或 `~/AGENTS.md`） | 所有项目、所有会话 |
| 项目 overlay | `<工作目录>/.jcode/prompt-overlay.md` | 仅当前项目，直接叠加 |
| 全局 overlay | `$JCODE_HOME/prompt-overlay.md`（或 `~/.jcode/prompt-overlay.md`） | 所有项目，直接叠加 |

系统提示词的完整分层与替换方式见 README 与 `crates/jcode-base/src/prompt.rs`。

### 注意事项

- **路径互斥**：引入 `JCODE_HOME` 后，原 `<主目录>/AGENTS.md` 不再生效，需迁移文件。
- **数据目录一致**：`JCODE_HOME` 同时决定 skills、日志、状态等位置，改动前确认旧数据无需迁移或已就位。
- **不要放失效规则**：宪法引用的 skill 需先确认已安装，否则规则只是空转。

## 三、技能与 MCP 配置

### 技能

从以下目录加载（首次安装会从 `~/.claude/skills/` 导入一次）：

- `~/.jcode/skills/<name>/SKILL.md`（全局）
- `./.jcode/skills/<name>/SKILL.md`、`./.agents/skills/<name>/SKILL.md`（项目）
- `./.claude/skills/<name>/SKILL.md`（兼容）

可用技能清单以静态列表写入系统提示词（名称 + 描述），智能体按需读取正文。
TUI 内 `/skill` 查看当前清单；`/skill-reload` 重新读取目录并加载新技能（项目技能按会话作用域隔离），
无需重启；也有 `skill_manage` 工具可列出/读取/重载。

### MCP

配置独立于 `config.toml`：

- `~/.jcode/mcp.json`（全局）
- `.jcode/mcp.json`（项目）
- 兼容 Claude Code 的 `~/.claude.json`（含 `projects.<abs_path>.mcpServers`）与仓库根 `.mcp.json`；
  `mcpServers` 与历史 `servers` 键都接受。

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "/path/to/mcp-server",
      "args": ["--root", "/workspace"],
      "env": {},
      "shared": true
    }
  }
}
```

当前只支持 stdio（命令式）服务器；HTTP/SSE 条目会被识别并跳过（有日志）。
首次运行时若 `~/.jcode/mcp.json` 不存在，会尝试从 `~/.claude.json`（或旧版
`~/.claude/mcp.json`）与 `~/.codex/config.toml` 导入。

TUI 内 `/mcp` 查看实时服务器列表，`/mcp-reload` 重新读取配置并在原地重连，无需重启。

其它常用配置位置：主配置 `~/.jcode/config.toml`、统一密钥文件 `~/.jcode/.env`、
集群模型路由指引 `.jcode/swarm-prompt.md`（`/swarm-prompt` 编辑）。
