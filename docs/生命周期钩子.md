# 生命周期钩子

jcode 可以在定义好的生命周期节点运行外部命令，让其他程序无需 fork jcode 就能观察或门控智能体行为。钩子补充了[派生钩子](派生钩子.md)（它控制*有头会话出现在哪里*）；生命周期钩子告诉你*它们内部发生了什么*。

## 配置

```toml
# ~/.jcode/config.toml
[hooks]
turn_end      = "~/bin/jcode-turn-notify"     # observer
session_start = ""                            # observer
session_end   = ""                            # observer
pre_tool      = "~/bin/jcode-tool-policy"     # gate
post_tool     = ""                            # observer
pre_tool_timeout_ms = 5000
```

环境变量覆盖（总是优先；空值禁用配置钩子）：
`JCODE_HOOK_TURN_END`、`JCODE_HOOK_SESSION_START`、`JCODE_HOOK_SESSION_END`、
`JCODE_HOOK_PRE_TOOL`、`JCODE_HOOK_POST_TOOL`、`JCODE_HOOK_PRE_TOOL_TIMEOUT_MS`。

## 通用契约

- 钩子命令行按 shell 风格解析（引号和反斜杠转义可用）但**直接**执行，不经过 shell。程序路径开头的 `~/` 会被展开。
- 钩子在已知时于会话工作目录运行。
- 每个钩子都会收到：

| 变量 | 含义 |
| --- | --- |
| `JCODE_HOOK_EVENT` | `turn_end`、`session_start`、`session_end`、`pre_tool`、`post_tool` |
| `JCODE_HOOK_SESSION_ID` | 事件所属的会话 |
| `JCODE_HOOK_CWD` | 会话工作目录 |
| `JCODE_HOOK_PAYLOAD` | 镜像所有字段的 JSON 对象（上限 16 KB） |
| `JCODE_HOOKS_DISABLED` | 总是 `1`；在嵌套的 jcode 调用中抑制钩子（递归守卫） |

## 观察者钩子

`turn_end`、`session_start`、`session_end` 和 `post_tool` 是**观察者**：分离派生、即发即忘。它们永远不会阻塞或拖慢智能体；失败只记录日志。

### `turn_end`

智能体回合完成时触发（流式回合路径，覆盖 TUI、桌面、集群工作者和无头会话）。

额外字段：`JCODE_HOOK_STATUS`（`ok`/`error`）、`JCODE_HOOK_DURATION_MS`、
`JCODE_HOOK_MODEL`、`JCODE_HOOK_LAST_ASSISTANT_TEXT`（前 4000 字符）、
`JCODE_HOOK_ERROR`（失败时）。

### `session_start` / `session_end`

`session_start` 在智能体会话变为活动时触发，`JCODE_HOOK_SOURCE` = `create`（全新）、`attach`（挂接现有会话对象）或 `resume`（按 id 恢复）。`session_end` 在正常关闭时触发（`JCODE_HOOK_SOURCE=close`）。

### `post_tool`

每次工具调用后触发。额外字段：`JCODE_HOOK_TOOL_NAME`、
`JCODE_HOOK_STATUS`、`JCODE_HOOK_DURATION_MS`、`JCODE_HOOK_OUTPUT_BYTES`（成功时）、`JCODE_HOOK_ERROR`（失败时）。

## 门控钩子：`pre_tool`

`pre_tool` 在**每次工具调用前同步运行**，可以阻止它：

- 钩子收到 `JCODE_HOOK_TOOL_NAME`，完整工具输入 JSON 通过 **stdin** 传入（以及 `JCODE_HOOK_TOOL_INPUT` 中截断到 16 KB 的副本）。
- **退出 0**：允许调用。
- **退出 2**：阻止调用。钩子的 stderr（修剪后，上限 2000 字符）作为工具错误返回给模型，因此模型可以适应。
- **其他任何情况开放失败**并记录警告：其他退出码、超时（`pre_tool_timeout_ms`，默认 5 秒）、二进制缺失、派生错误。

开放失败是故意的：坏掉的策略脚本应降级为"无策略"，而不是弄瘫每个会话。如果需要失败关闭语义，让钩子自己健壮（它是你的信任边界，不是 jcode 的）。

### 示例策略脚本

```bash
#!/usr/bin/env bash
# ~/bin/jcode-tool-policy
# stdin: 工具输入 JSON。Env: JCODE_HOOK_TOOL_NAME, JCODE_HOOK_SESSION_ID...
input=$(cat)

case "$JCODE_HOOK_TOOL_NAME" in
  bash)
    if grep -qE 'rm -rf /([^a-zA-Z]|$)|mkfs|dd if=' <<<"$input"; then
      echo "blocked: destructive shell command" >&2
      exit 2
    fi
    ;;
  write|edit)
    if grep -q '"file_path":"/etc/' <<<"$input"; then
      echo "blocked: writes to /etc are not allowed" >&2
      exit 2
    fi
    ;;
esac
exit 0
```

## 示例：回合结束时 tmux 状态 + 桌面通知

```bash
#!/usr/bin/env bash
# ~/bin/jcode-turn-notify
if [ "$JCODE_HOOK_STATUS" = ok ]; then icon=✅; else icon=❌; fi
tmux display-message "jcode $icon ${JCODE_HOOK_SESSION_ID:0:12}" 2>/dev/null
notify-send "jcode turn $JCODE_HOOK_STATUS" \
  "${JCODE_HOOK_LAST_ASSISTANT_TEXT:0:120}" 2>/dev/null
exit 0
```

## 示例：所有钩子活动的 JSON 事件日志

把多个钩子指向一个脚本并按 `JCODE_HOOK_EVENT` 分发：

```bash
#!/usr/bin/env bash
# ~/bin/jcode-event-log
echo "$JCODE_HOOK_PAYLOAD" >> ~/.local/state/jcode-events.jsonl
```

```toml
[hooks]
turn_end      = "~/bin/jcode-event-log"
session_start = "~/bin/jcode-event-log"
session_end   = "~/bin/jcode-event-log"
post_tool     = "~/bin/jcode-event-log"
```

## 设计说明

- 钩子查找由配置驱动，配置重载时重新读取；无需重启 jcode 即可添加或更改钩子。
- 热路径（`pre_tool`/`post_tool`）在构建任何载荷之前检查是否配置了钩子，因此未配置的钩子几乎零成本。
- 递归守卫（`JCODE_HOOKS_DISABLED=1`）意味着钩子可以安全地调用 `jcode` CLI 命令，而不会在嵌套进程中重新触发钩子。
